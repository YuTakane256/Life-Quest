# Mobile称号の保存復元：値の検証と遅い読込の拒否（2026-11-07）

計画④ / #699・#941。#940マージ後のmain `464882a2`を基準とする。

## 問題と修正

[Mobile称号ストア](../apps/mobile/src/stores/useMobileTitleStore.ts)はpersistの既定mergeを使い、保存内容を検証せずストアへ混ぜていた。不正な型の`activeTitle`が描画用の値へ入り、保存内の`setActiveTitle`や余分なフィールドで操作/状態を置き換えることもできた。また、遅い保存読込は認証切替後のクリアや、新しい選択・解除を古い称号で戻していた。

保存は既存の`activeTitle`だけに限定し、復元時もその明示フィールドだけを採用する。既存のtrim・40文字・不正型はnullという正規化を通し、rootが不正/配列/称号欠落なら現在値を保持する。操作関数と余分な保存値を取り込まない。

読込開始時に認証世代とメモリ更新世代を捕捉し、完了時に一致しなければ現在のストアを維持する。更新世代は実ストアへの書込を購読し、画面の選択だけでなく、cloud seedや認証処理による`setState`も対象にする。同値の明示解除、一度変更して元に戻した場合も旧読込を採用しない。世代はメモリ上だけで管理し、保存形式へ追加しない。

同じ本人の重複通知は復元を失効させず、A→logout→Aは別世代として拒否する。重複したrehydrateでは、導入済みpersistの最新読込を採用する契約を実APIで確認する。保存キー`quest-board-title`、version 1、`state.activeTitle`の形式は維持する。

## 検証

[実persist/storeの回帰23件](../apps/mobile/src/stores/mobileTitleRestore.test.ts)を追加。AsyncStorage APIだけをメモリ上のスタブにして、成功/失敗/遅延を制御する。認証世代は実auth lifecycleを使い、サーバー認証/実端末ディスクの合格とは区別する。

- 初期22件は修正前16失敗/6成功。文字列/null/空白/長さ・不正型、操作関数の上書きや余分なフィールド、不正/欠落root、JSON破損/読込拒否と次の正常読込を確認する。
- A→B、logout、A→logout→Aの読込待ちで、旧保存が新しい表示へ戻らない。同じ本人の重複通知では正常復元を維持する。
- 読込中の新しい選択、同値の解除、一度変更して戻した値を保持する。復元から追加のenqueueを起こさず、通常の選択による送信は維持する。
- 追加1件で、後から開始した読込の成功後に古い読込が完了しても巻き戻らないことを確認する。
- 実set/保存/rehydrateでversion 1と称号フィールドだけを照合し、既存の設定・送信・受信/保存読込通知の回帰を維持する。同期品質unitコマンドにも追加する。

全体テスト、Web/Mobile型検査・Lint・secrets・ビルド、実DB/Edgeを含む通常CI3件、PR作成後の独立レビューの確定結果はPR/Issueに記録する。実DBの新しいケースは追加しない。
