# Webの画面移動を越えた宝箱開封・再送（2026-11-01）

計画④ / #699・#903 / T07。PR #902マージ後のmain `55e1ed1c`からの修正。

## 不具合と変更

[キャラ画面](../src/pages/CharacterPage.tsx)内で宝箱開封フックを生成していたため、開封の失敗後に在庫やタスクへ移動すると、宝箱ID・冪等キー・再送案内を失う。処理中の移動後には新しい画面に排他状態も残らない。

[宝箱操作provider](../src/components/character/ChestOperationsProvider.tsx)を[App](../src/App.tsx)のRoutes/Suspense外に置き、キャラ画面は[同じ操作context](../src/hooks/useChestOperations.ts)を参照する。合成用providerと責務を分けたまま、開封失敗から戻っても同じ宝箱・同じ冪等キーで再送する。開封中は他の宝箱も含めてボタンを無効にし、何も起こらない有効ボタンを残さない。

[既存の開封フック](../src/hooks/useCloudChestOpen.ts)の認証scope・サーバー結果の判定・キー管理・ローカル抽選条件は変更しない。本人の開封が画面離脱中に成功した場合、既存ストアで一度反映し、App全体にある共通宝箱演出へ渡す。自動的な画面移動はしない。演出の「バトルへ」等は従来どおり本人の操作と既存イベントscopeで判断する。

AからBへ切り替わると、Aのキー・エラー・処理中表示は破棄する。遅れたAの結果やfinallyがBの宝箱/装備/演出・進行中状態を変更しない。App全体のunmount後も旧結果を適用しない。通常同期が先に開封済みと装備を反映した場合、既存ストアの冪等ガードにより装備・演出を重ねない。

## 検証

[実App・キャラ画面の回帰](../src/hooks/chestNavigation.test.tsx)を6件追加。App/BrowserRouter/CharacterPage/在庫画面/ストア/共通宝箱演出は実装を使用する。認証・通信、無関係なページ/通知/演出はスタブにし、実ブラウザー・実回線の合格とはしない。

修正前は2失敗/4成功。画面移動後に再送案内/同キーを失い、開封中のボタン状態が失われることを再現した。修正後は次を確認する。

- 開封失敗→在庫→タスク→キャラ→通常の再送で同じ宝箱/キー、装備/開封済み1件/演出が各1回分。
- 開封中の移動と復帰で同じ/別の宝箱を二重送信せず、離脱先のタスク画面のまま本人の結果・共通演出を受け取る。
- ログアウト/Bログイン後は旧再送状態を出さず、新キー・送信先Bを使用。遅いA応答はB処理を解除せず、B結果だけを反映。
- App全体unmount後は旧応答を適用しない。
- 同期が先に開封済み・装備中の結果を取り込んだ場合、遅い応答で装備の重複/装備状態の巻戻り/再演出がない。

同期品質コマンドにも追加する。プロフィール編集の既存テストは新contextをmockするよう配線だけを変え、assertionは維持した。合成のApp回帰には未使用の宝箱API stubを明示し、合成の検証内容は維持する。全体・型・Lint・ビルド・独立レビュー・同じHEADのCI3件の結果はPRとIssueに記録する。

## 範囲と残り

同じ起動中App・認証セッション内の画面移動が対象。ブラウザー再読込・OS終了後の永続再送、未完了開封の実プロセス再起動、Native画面の寿命は別条件として残す。実stagingの開封応答喪失は[既存の限定実測](staging-chest-reward-retry-20261027.md)を維持し、今回のUI/通信スタブ回帰を新しい実staging確認の代替にしない。

DB/RLS/API/保存形式/報酬ルール・台帳/依存/Native実装を維持する。今回は実ユーザー/staging・秘密値・利用中データへ操作せず、公開・配布・デプロイ・自動マージしない。レイアウト/画像素材を変えないため比較画像追加なし。④継続、⑤移行・安全性全体の認定は未宣言。
