# ログアウト・アカウント切替の表示データ分離

対象: #729。主要体験の品質確認のうち、認証ライフサイクル通知を境界にした
Web/Mobileのストア初期化を検証します。画面デザイン、DB、同期API、報酬量は変更しません。

## 修正した不具合

- クラウド反映後のログアウトで、Web/Mobileの統計ログ、Mobileの称号、
  Webの戦闘履歴が残っていました。既存のタスク・習慣・ゲームと同じ初期化に含めます。
- ログアウトを挟まずAからBへ切り替えると、Aの反映済みデータがBの移行・同期フックにも
  見えていました。ストアフックが先にクリアすることで、統計の単調マージがAの大きい値を
  Bへ引き継ぐ問題も防ぎます。アプリ起動時の登録順（ストア→移行→outbox→同期）は維持します。
- 統計だけを受信したセッションも既存の習慣セクション判定によって反映済みになります。
  その場合も統計が初期化される回帰テストを追加します。シード可否の既存判定は変更しません。
- ストアクリアから同期停止フックまでの待機中に旧pullが到着する窓も、
  既存の認証スコープガードで通知開始時点から無効にします。
  ログアウトが待機中に同じユーザーへ再ログインした場合も、失効した同期ハンドルは再生成します。

## 保護するデータと範囲

- 初回ログインの匿名データは初回移行元なのでクリアしません。
  同一ユーザーの再通知でも進行をクリアしません。
- クラウドがまだ一度も反映されていないセッションは、既存の匿名データ保護条件を維持します。
- ユーザー別クラウドキャッシュ・outboxの保存領域は削除しません。
  クリア対象は表示用ストアと、そのZustand persistの保存値です。
- Webの戦闘履歴はローカル履歴です。反映済みアカウントから離れると表示・保存値を空にし、
  再ログインでの過去履歴の復元は保証しません（クラウド履歴同期の追加ではありません）。
- Webの期限切れセッション回復は、統計・戦闘履歴も既存の復旧用コピーに含めてからクリアします。
  コピー保存が失敗したら元データを残します。復旧用コピーの自動復元UIは追加しません。
- Mobileの統計初回シードフラグをリセットし、各ストアのhydrationフラグ・アクションは維持します。
  テーマ・動きの量・通知設定は従来どおり端末側の表示設定として維持します。

## 回帰テスト

```bash
npx vitest run src/platform/authStores.test.ts apps/mobile/src/platform/authStores.test.ts src/platform/cloudSync.test.ts apps/mobile/src/platform/cloudSeed.test.ts src/platform/cloudSyncSession.test.ts
```

実ストアを使い、シード後ログアウト、初回/同一ユーザーログイン、直接A→B、
Bの低い統計値の反映、統計のみの受信、Webの保存再読み込み、
MobileのAsyncStorage書き込み内容、回復コピーの成功/失敗を検証します。
フック内の例外はライフサイクル側で握りつぶされるため、後続フックが見た値を採取し、
フック外で検証します。旧pullの待機競合は制御可能なPromiseとモック保存領域で検証します。

## 未確認・対象外

- Supabaseに実際の異なる2アカウントで接続するE2E、オフライン再送、iOS/Androidでの
  実ログイン・再起動は別途確認が必要です。ストアの自動テストを実環境での成功とは扱いません。
- 認証SDKが通知する前、起動時の全hydration競合、全移行処理の非同期コールバック、
  既に開始した通信/保存I/Oの取消やアカウント削除の原子性までは保証しません。
- 未シード匿名データの帰属判断、複数タブのクラウドアカウント協調、履歴のユーザー別保存は
  今回の変更に含めません。全アカウント分離の完成や公開準備完了を意味するものではありません。
