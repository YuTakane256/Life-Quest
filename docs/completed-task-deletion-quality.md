# 完了タスク一括削除の確認対象固定（#759）

## 問題

Web/Mobileとも、確認画面の確定時に`deleteCompletedTasks()`で「その時点の全完了タスク」を削除していた。
確認を開いている間に新しく完了したタスクやUndo待ちを終えたタスクまで追加され、
承認した件数より多く削除され得た。確認前後のログアウト/アカウント切替やNativeタブ離脱も
確認callbackの寿命とは結び付いていなかった。

## 変更

- 確認を開く時点の「完了済みかつUndo待ちではない」タスクと件数を固定する。
- 名前・期日・優先度・タグ・繰返し・完了情報・作成日時・サブタスクの内容を値で保存し、確定直前に照合する。
  同値pullやオブジェクトのキー順変更は許可し、入れ子の変更も区別する。
- 後から完了した/Undo待ちを終えた未承認タスク、内容変更されたタスク、現在未完了のタスク、
  現在Undo待ちのタスクは残す。未変更の承認タスクだけを削除するので、一部変更があっても対象を広げない。
- ストアにも承認ID集合を渡し、最新の完了/Undo待ち状態を再確認して一度の更新で削除する。
  `delete_task` outboxは実際に削除したIDにだけ作る。空の集合は削除なし、引数省略の既存API動作は維持する。
- 確認は1回だけ使える。キャンセル、確認の置換、認証世代変更、画面離脱で旧callbackは無効になる。
  Nativeは保持されたタブからのblurも失効し、戻っても復活しない。同一ユーザー再通知は維持する。
- Webの確認件数は途中の一覧更新で増えない。NativeのOS Alertを強制的に閉じるAPIは使わないが、
  古いAlertから確定しても削除しない。
- 前回のインベントリ用Reactスコープを`useInteractionScope`へ名称整理して再利用する。
  本体の動作は変えず、インベントリの回帰も実行する。

DB/API、保存形式、報酬台帳、XP/統計計算、5秒Undoのルール、通常の画面配置・確認文言は変更しない。
この確認のために通常アプリや保存データを初期化しない。

## 検証

- `packages/core/src/completedTaskDeletion.test.ts`：固定対象、全フィールド、サブタスクのin-place変更、
  同値clone/キー順、後からの完了、削除/Undo待ち、空の承認、ストア用のID制限。
- `src/hooks/completedTaskDeletion.test.tsx`：実Web/Native画面と実ストア、実Web確認ダイアログを使う。
  Nativeの部品/Alert/focus、outbox通信、トーストはモック。保存した旧callbackも直接呼び、
  A→B、A→logout→A、unmount、blur/復帰、cancel、二度確定、新確認との競合、同値pull、
  再描画前の切替、変更対象の温存、削除したIDだけのenqueueを確認する。
- `e2e/completed-task-deletion.spec.ts`：PC/スマホ幅×ライト/ダークで実確認画面のcancel→再確認を操作。
  開いたまま一時ブラウザープロファイル内の実ストアへ同期相当の変更/完了を反映し、
  確認件数が2のまま、未変更1件だけ削除され、更新分と新完了が再読込後も保存されることを検証する。
- 既存のタスク削除・Undo・報酬・outbox回帰と、名称整理したインベントリ回帰を維持する。

画面構成を変更しない安全性修正なので新しい比較画像は追加しない。
Web E2Eは一時プロファイル、Native単体はモックAsyncStorageだけを使う。
通常確認用Metro8081を止めず、利用者のシミュレーターデータは消さない。

## 残る境界

Native OS Alertとタブ移動の実iOS/Android操作、staging二端末での実同期は別途確認する。
削除送信後のサーバー上の変更/競合を予約・ロックするAPIは追加しない。
現在の値が完全に元へ戻った編集履歴まで識別するバージョン番号も追加しない。
個別タスク/サブタスク/習慣の削除や編集フォーム、休息日など、他の画面操作の確認全体を
今回の完了範囲には含めない。
