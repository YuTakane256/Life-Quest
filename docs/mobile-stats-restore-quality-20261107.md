# Mobile統計の保存読込：認証切替後の再投入を防ぐ（2026-11-07）

計画④ / #699・#943。#942マージ後のmain `b114cde8`を基準とする。

## 問題と修正

Mobileの統計ログはAsyncStorageから非同期で復元する。読込開始後に認証が切り替わっても既存のmergeは保存値を取り込み、ログアウト/別アカウントへの切替でクリアしたタスクXP・習慣ログ・初回seed済みフラグを元へ戻していた。Bの新しい受信ログが先に届いた場合もAの古い保存値に置き換わる。

[統計ストア](../apps/mobile/src/stores/useMobileStatsStore.ts)の読込開始時に、既存の認証ライフサイクルの世代を捕捉する。merge時に失効していれば現在値を維持する。同じ本人の重複ログイン通知やトークン更新では世代が変わらないため通常復元を維持し、A→logout→Aは別世代として拒否する。この判定は認証・認可の代替ではない。

拒否した読込でも既存の完了コールバックを通すため、`hasHydrated`とpersistの完了通知は進む。Bの後続の新しい読込は正常に復元できる。保存キー`quest-board-mobile-stats`、version 1、taskXpLog/habitLog/seededの3フィールド、正規化と通常の追記・初回seed・クラウドの単調マージは維持する。保存の削除や移行は行わない。

## 検証

[実ストア/persistの回帰12件](../apps/mobile/src/stores/mobileStatsRestore.test.ts)を追加。AsyncStorageのAPIだけをスタブにし、実認証ライフサイクルと、認証クリアについては実Mobile認証フックを使う。

- 修正前7失敗/5成功。A→B、logout、A→logout→Aを、表示の書換なしの認証変更だけでも検証する。
- 実フックのクリアとBのクラウド受信後に、Aの旧ログ/seededが戻らない。拒否後の追記操作も使える。
- 同一本人の無変更/重複通知/トークン更新、匿名の通常復元を維持する。seed済み履歴を空のコレクションから再構築しない。
- 拒否後のBの正常読込・追記・version 1の保存内容と、重複読込で最新世代の復元を維持することを確認する。

関連6ファイル80件が成功。新テストを同期品質unitコマンドにも追加する。全体テスト・Web/Mobile型検査・Lint・secrets・ビルド・通常CI3件・独立レビューの最終結果はPR/Issueに記録する。DB/Edgeの新規ケースは追加しない。

## 範囲と残り

今回の修正はMobile統計の**認証世代を跨ぐ読込**に限定する。同一認証内の更新と読込の全競合解決、所有者を記録しない保存データの出自確認、旧書込の取消・物理ディスク/OS終了後の耐障害性は保証しない。ほかのストア全体の復元を合格にしない。

DB/RLS/API、XP/報酬計算、依存、Webの保存処理、UI配置は変更しない。配置や素材を変更しないため比較画像は追加しない。実staging・承認済みA/B・利用データ・OS/Simulator/Dockerを操作しない。④継続、⑤未開始。マージ・配布・デプロイは行わない。
