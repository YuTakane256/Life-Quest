# Webの画面移動を越えた戦闘開始・再試行（2026-11-05）

計画④ / #699・#909 / T07。PR #908マージ後のmain `5344c0b9`からの修正。bot #905/#906の依存更新とは独立する。

## 不具合と変更

[マップ画面](../src/pages/MapBattlePage.tsx)内で戦闘開始フックを生成していたため、開始に失敗/処理中のままタスク等へ移動すると、開始ステージ・操作キー・失敗案内・排他を失う。戻って別キーの新規要求を出せる一方、同じ試行を既存の「再試行」で再送できない。

[開始provider](../src/components/battle/BattleStartProvider.tsx)を[App](../src/App.tsx)のRoutes/Suspense外に置き、マップ画面は[同じ開始context](../src/hooks/useBattleStart.ts)を参照する。[既存の開始フック](../src/hooks/useCloudBattleStart.ts)のキー管理・認証scope・開始元戦闘の検査は変えず、同じApp内で保持する。復帰だけでは自動再試行せず、通常の「再試行」で同じステージ/キーを使う。処理中は開始ボタンを引き続き無効化する。

次ステージ開始で渡していた画面ローカルのコールバックは取り除く。ローカル勝利と確定済みクラウド勝利は既に最高到達を記録しており、開始ストア処理が対象ステージ・HP・行動列・ログ等を初期化するため、再試行時に古い画面のstate setterや重複したadvanceStageを実行しない。次のステージ番号と最終ステージの再挑戦を維持する。

離脱中に本人の開始応答を受け取った場合、同じ戦闘を既存ストアへ反映し、現在routeは変えない。自動攻撃のタイマーは従来どおりマップ画面内にあるため離脱先で進めず、戻ると戦闘を再開する。A/B切替・App全体のunmount・開始元戦闘の変更後は旧応答を適用しない。旧AのfinallyはBの開始状態を解除しない。匿名開始と、操作前には認証/開始通信を行わない動作を維持する。

## 検証

[実App・マップ・ストアの回帰](../src/hooks/battleStartNavigation.test.tsx)を10件追加。App/BrowserRouter/MapBattlePage/ゲーム・履歴ストアは実装を使い、認証/通信と無関係なページ/通知/演出はスタブとする。

基本8件は修正前3失敗/5成功。失敗後の再試行喪失、処理中復帰の排他喪失、次ステージ失敗後の再試行喪失を再現する。追加2件は、画面コールバック除去に伴う匿名の次ステージ・最終ステージ再挑戦の実ストア動作を確認する。

- 失敗→タスク→マップで同じステージ/キーを明示的に再送し、開始を一つに保つ。
- 開始中の復帰でもボタンを無効にし、別要求を送らない。離脱中の応答はrouteを変えず戦闘へ反映、XP/履歴/行動列/ログを増やさない。
- 確定済み勝利から次ステージへの再試行で同じキーを保持し、進行/報酬を重ねない。
- 匿名の次ステージとクラウドの最終ステージ再挑戦で、最高到達を余分に進めず報酬/履歴を重ねない。
- 離脱中のA/B切替と遅延応答で、B開始状態を旧Aが解除せずBだけを反映。ログアウト後の新規B要求は旧キー/エラーを継承しない。
- App全体終了後と、開始元戦闘の変更後の応答を拒否。変更後は新たな要求が可能。
- StrictModeの匿名起動・マップ表示だけでは認証/開始通信せず、明示操作でローカル戦闘を開始。

既存マップ表示テストのmock先をcontextへ変え、次ステージのassertionはコールバック不要の引数へ合わせる。宝箱・合成のApp回帰には未使用の開始API stubだけを追加し、既存assertionは維持する。同期品質コマンドにも追加。全体・型・Lint・ビルド・独立レビュー・最終HEADのCI3件の結果はPR/Issueに記録する。

## 範囲と残り

同じApp起動中の画面移動が対象。再読込/OS終了後のキー永続化・未確定戦闘の実プロセス再起動、Nativeの画面寿命・実回線断、実機認証・配布は別条件として残す。実stagingの結果再送は[既存の限定記録](staging-battle-reward-retry-20261027.md)を維持し、今回を新たな実staging合格としない。

共有開始ポリシー・rawフック・サーバーAPI・DB/RLS・保存形式・報酬・依存/Nativeを維持する。実ユーザー/staging・秘密値・利用中データへ操作せず、マージ/デプロイ/公開/配布しない。レイアウト/画像素材変更なし、比較画像追加なし。④継続、⑤移行や全体の安全性認定は未宣言。
