# Mobile自動戦闘の認証切替とAppState現在値の保護（2026-11-05）

計画④ / #699・#915 / T07。Web対応 #914 マージ後のmain `06051cc3` が基準。

## 問題と変更

Mobileは既にfocus/AppState通知で自動攻撃を停止していた。しかし、初回ログインでは匿名の移行元データを保つため、実行中のlocal戦闘も残る。表示中のマップで認証世代だけが切り替わると、古い時計が止まったまま戦闘runtimeが残り、新しい戦闘へ進めない。

[自動戦闘フック](../apps/mobile/src/hooks/useAutomaticBattle.ts)で認証切替時に時計を停止し、その時計が捕捉したactors・stage・attempt・rewardModeに一致する実行中local戦闘だけを片付ける。保存済みXP・進行・装備・未開封宝箱・報酬台帳は保持する。先に別の戦闘へ置き換わっていれば片付けず、同一所有者の認証通知でも時計を変えない。cloud戦闘の切離しは既存の認証ストア処理を使う。

時計の開始時と攻撃直前にAppState.currentStateも確認する。最後に受信した通知がactiveでも、現在値がbackground・inactive・nullなら停止する。active通知で戻った後は新しい一間隔を待ち、過去の経過時間をまとめて攻撃しない。世代番号で停止前の予約済みcallbackも拒否する。

通常の攻撃間隔・手動スキル・勝敗処理・報酬計算・既存のfocus/画面離脱・hydration保護は維持する。DB/RLS/API・同期/移行・保存形式・依存関係は変更しない。

## 検証

[Mobile自動戦闘回帰](../src/hooks/mobileAutomaticBattle.test.tsx)に9件追加し、29件とする。実際のMobileフック・ゲームストア・対象ケースの認証ストアフックを使用し、AppState/useFocusEffect・AsyncStorage・ログインボーナスの境界をスタブ化する。React StrictModeとfake timerでタイミングを制御する。

修正前は7失敗/22成功、修正後は29件成功。関連するWeb戦闘・認証・ゲームストアも含む170件が成功した。

- background・inactive・nullへの現在値変化を、change通知なしでも攻撃前に検知する。
- 復帰後は一間隔待ち、旧callbackからの攻撃を防ぐ。
- 匿名→初回ログインで表示中の旧local戦闘だけを終了し、保存済み進行/装備/宝箱/台帳を残す。
- 別アカウント・ログアウト→再ログイン後に旧戦闘を復活させず、報酬を増やさない。
- 先行する認証購読で作られた新しい戦闘は清掃しない。同一所有者通知では時計の位相を維持する。

同期品質のunit対象にもこの既存ファイル全体を追加する。全体テスト・型検査・Lint・秘密値ガード・Web/PWAビルド・匿名Android export・独立レビュー・最終HEADの通常CI3件の結果はPR/Issueに記録する。

## 範囲と残り

Nativeのマップ画面そのものを実端末で操作したテストではなく、フックと実ストアを使ったJS回帰である。AppStateの現在値と受信済み通知の不一致を模擬しており、全OSのイベント順序・サスペンド・実時間制御まで保証しない。実機のバックグラウンド復帰、実stagingの認証切替・未確定戦闘の再起動は別途残る。再起動後に同じattemptを継続する仕組みは追加しない。

実ユーザー/staging・秘密値・利用中データ・DB・OS/Simulatorの操作は行わない。画面構成/素材は変わらず、比較画像は追加しない。④は進行中、⑤の配布準備は未開始。マージ・配布・デプロイは行わない。
