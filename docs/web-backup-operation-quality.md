# Web手動バックアップ：操作・認証境界の品質確認

関連: #751、親計画 #699 / #693。初回移行・Mobileの手動統合とは別の、
Web設定画面のJSON保存/復元を対象とする。

## 修正

- 保存・読込・確認・復元を、操作インスタンスと認証スコープ、画面の生存期間に帰属させる。
  別ユーザーへの切替、ログアウト→同じユーザーへの再ログイン、画面離脱で破棄する。
  同じユーザーの重複通知では破棄しない。
- 新規ファイルの選択は、古い読込結果/エラー/確認候補を置き換える。
  古い候補の承認から別の候補を復元しない。
- 認証初期化の完了と既存ゲーム保存/Web Lockを待ち、ロック内の実際の読み書き直前にも
  帰属を確認する。待機中の復元取消は書き込みを行わない。
- 保存/復元の多重起動を同期的なrefで防ぎ、処理中表示とボタン無効化を追加する。
  復元成功から再読み込みまでの追加操作も受け付けない。
- エラー消去のタイマーを破棄し、古い処理が新しい操作や別画面に影響しないようにする。
  復元成功時は書き込みと同じ同期処理内で即座に再読み込みを開始する。
  成功後の画面離脱で再水和を取り消したり、旧メモリから復元結果を再保存したりする猶予を残さない。
  ダウンロードの一時URLはクリック失敗時も解放する。

## 自動確認

`src/components/ui/DataBackupSettings.test.tsx` はStrictModeの実DOMで32ケースを確認する。
バックアップの変換/検証/Storage書き込みとダウンロード用Blob/リンクは実装を使用し、
ファイル読込・待機時間・ブラウザー再読み込みを制御する。Web Lockの2ケースでは
本番の`withSettledGamePersistence`も使用し、ロック獲得をテストで遅延させる。

- 通常の保存/復元/再選択、プレビュー/取消、連打、処理中表示
- 古い読込の成功/失敗、新しい候補、サイズ/拡張子/MIME/JSONの拒否
- 保存/復元待ちの認証切替、同一ユーザー通知、ログアウト→同じユーザー、画面離脱
- 認証初期化中の新しい操作、旧操作完了と新操作の進行状態
- 書き込み失敗時の既存値復旧、古いエラー消去の取消、コミット時の即時再読み込み

既存の`dataBackup.test.ts` / `backupSummary.test.ts`と併せて、保存形式や検証の回帰も確認する。

`e2e/data-backup.spec.ts`では、デスクトップ/スマホ幅のChromium × ライト/ダークの4ケースで、
匿名のタスク作成→実際のJSONダウンロード→追加作成→取消→不正ファイル拒否→
同じJSONの復元→実際の再読み込みを確認する。バックアップ内の名前/整合性情報と、
復元後のタスク一覧・保存値が選択したスナップショットに戻ることも検証する。

## 変更しない範囲・残確認

DB/同期API/バックアップ形式/報酬計算は変更しない。カード配置・通常時のプレビューは維持する。
インポート済みデータの由来を認証する機能や、複数タブ・全ストアのトランザクション化ではない。
書き込み開始後の同期処理は中断せず、既存の失敗時best-effort復旧を維持する。

自動テストの合格はstagingの実アカウント同期、実端末/ブラウザーのファイルダイアログ・
ダウンロード、タスク以外も含めた全ストアの復元後再水和が合格した意味ではない。
これらの実環境確認は残す。
