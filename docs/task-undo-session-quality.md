# タスクの5秒取消とアカウント境界（#745）

## 現象

Mobileのクラウド表示クリアはtasksだけを消し、pendingCompletionsを残していた。
同IDのタスクが再投入されると、旧5秒タイマーやバックグラウンドflushが
新しい表示を確定し、報酬・繰り返し・送信を行える。
Web/Mobileの取消表示にも認証スコープや期限の実行直前チェックがなかった。
特に複製の取消はdeleteTaskを呼ぶため、古い操作を新アカウントへ持ち越してはいけない。

## 契約

- 5秒待機中の完了は未確定。アカウントAからログアウト/別アカウントへ移る場合は取り消す。
  切替前に完了を確定したい場合は5秒経過を待つ。確定済み報酬を巻き戻す変更ではない。
- scope通知時に旧タイマーとpendingを解除する。前段のasync認証フックが遅れても、
  その間のtimer/flushから旧処理を実行しない。
- 完了表示を戻すのはpendingのtaskIdとcompletedAtが一致する項目だけ。
  未seedでも他のタスクや既存の進行は削除しない。
- 初回anonymous→ログインの移行元と同一ユーザー再通知のpendingは維持する。
  A→logout→Aは旧待機を再開せず、新たな操作として扱う。
- 直接の全表示クリアもpendingとタイマーを破棄する。
- Webの確定後の動的import/匿名報酬lock待機にもスコープガードを追加。
  切替後に旧統計・繰り返しタスク・complete_taskを新スコープへ適用しない。
- Mobileは確定処理中にストア購読者が同期的に認証を変えた場合も、以降の処理を停止する。
- Web/Mobileの取消callbackはスコープ・マウント・現在の通知・期限を実行前に検証する。
  scope変更で表示とタイマーを消し、unmount後は旧操作を無効にする。
- 通常の5秒猶予、Web最大3件/Mobile1件、メッセージ/レイアウトは維持する。

DB・保存形式・報酬量の変更や保存データ初期化は行わない。

  A→logout→A、直接クリア、Webロック待ち/確定後awaitの境界を確認。
  通信とボーナス専用フック、Mobile保存アダプターはモック。

  unmount・通知入替・Web3件上限を検証。Mobileのネイティブ描画を検証したものではない。
- 既存のタスク取消・繰り返し・報酬台帳・認証ストア回帰は維持する。
