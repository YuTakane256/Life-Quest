# ADR-011: 初回クラウド移行はWeb基準、Mobileはバックアップ後置換

- 状態: 承認済み（人間決定 2026-07-04）
- 関連Issue: #506

## 文脈

WebとMobileの両方に既存のローカルデータ（タスク・習慣・ゲーム進行）が存在し得る。初期案は「先に移行した端末が基準、2台目は差分確認の3択UI」という対称的な調停だったが、複雑でユーザーにも分かりにくい。

## 人間決定

1. **初回クラウド移行はWebデータを基準にする。** Webのローカルデータがそのままクラウドの初期状態になる。
2. **Mobileの既存ゲーム状態（キャラクター・装備・宝箱・マップ/バトル進行）は、ローカルへバックアップした上でクラウド（Web由来）の状態へ置き換える。** どちらを残すかをユーザーに選ばせる調停は行わない。
3. **Mobile固有のタスク・習慣（クラウドに存在しないもの）は、ユーザーの確認後に統合可能にする。** 自動統合はしない。
4. **移行完了後はSupabaseを唯一の正とする。** ローカルデータ（quest-board-*・canonical envelope）はオフラインキャッシュ・バックアップの位置づけになる。

## 実装方式（#506）

- フローA（Web初回移行）: `profiles.imported_at` 未設定のアカウントへの `import_snapshot` はWebからのみ受け付ける。コレクション・ゲーム状態・報酬台帳証跡（xp_delta=0）・stats_dailyを1トランザクションで投入し、`imported_at`/`migrated_from='web'` を設定する。
- フローB（Mobile初回接続）: ゲーム状態は `life-quest:cloud:{userId}:pre-migration-backup:v1` へバックアップ後、通常の `pull_sync_batch` シードでクラウド値に上書き（サーバーへは送らない）。Mobile固有のタスク・習慣は確認UIで承認されたものだけ `import_mobile_content` で挿入する。

## 帰結

- 「2台のXPを足す」「最大値に引き上げる」等の自動マージロジックが不要になり、二重計上・改ざんの余地が消える
- Mobile固有のゲーム進行は失われる（バックアップには残る）。Mobileユーザーへの事前告知が必要
- 3台目以降の端末は、初回移行完了後は通常ログインとして扱う想定（明示確認が必要になれば別途決定）
