# ADR-010: バトル報酬はbattle_attempt_id単位・再攻略で毎回獲得可

- 状態: 承認済み（人間決定 2026-07-04）
- 関連Issue: #502・#509

## 文脈

Web現行（src/stores/useGameStore.ts:79,108,568,661）はクリア済みステージの再攻略を許可し、勝利のたびに全XPを再付与する。サーバー権威化にあたり「初回のみ」へ制限するか、現行挙動を維持するかの決定が必要だった。また、クライアントが「勝った」と自己申告するだけの設計では不正な勝利報告を防げない。

## 人間決定

1. **バトルは再攻略でも毎回XPを獲得できる。** ステージ単位で報酬を一度に制限しない（タスク/習慣の「生涯1回」＝ADR-003とは意図的に異なる扱い）。
2. **冪等性はサーバー発行の `battle_attempt_id` 単位で保証する。** 防ぐのは「同一戦闘結果の二重送信」だけであり、同じステージへの新しい挑戦（新しいattempt）は毎回新規の報酬機会になる。
3. **戦闘開始と勝利検証もサーバー権威にする。** 不正な勝利報告を防ぐ。

## 実装方式（#502）

- `start_battle_attempt(stage, key)`: ステージ解放条件（`stage <= max_cleared_stage + 1`）をサーバーで検証し、敵ステータス（core `BATTLE_CONFIG`）と自キャラ実効ステータス（characters + 装備から算出。クライアント申告値は使わない）をサーバーが確定して `battle_attempts` 行を発行する。
- `resolve_battle_attempt(battle_attempt_id, actions, key)`: クライアントが提出したターン行動列を、attempt発行時のスナップショットを初期値として**サーバーがcoreの戦闘計算で独立に再計算**し、勝敗を確定する。勝利なら `reward_transactions (kind='battle_reward', source_id=battle_attempt_id)` へ挿入。`status != 'in_progress'` のattemptへの再送は拒否し既存結果を返す。敗北もresolvedにして再送を許さない。

## 帰結

- ゲームバランス上、バトル周回によるXP獲得はWeb現行と同じく設計値（ステージのxpReward）の範囲で可能なまま維持される
- サーバー再計算のため、バトルのターン処理関数はcoreへ純関数として共有化される必要がある（#509が前提）
