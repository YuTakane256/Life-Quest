# デイリーログインボーナスのセッション境界（#741）

## 対象と変更

Web/Mobileのログインボーナス請求・再確認・受領表示を保護する。
DB・報酬量・streak計算・保存形式を変更せず、保存済みデータを初期化しない。

- 確認開始時に認証スコープを捕捉し、専用フックの世代番号と併せて有効性を確認する。
  前段の認証ライフサイクルフックを待ってから認証SDKを読み、旧スコープの処理は停止する。
- SDK主体とライフサイクルの所有者が一致しない場合は送信・受領状態の変更を行わない。
  認証済みスコープでSDKがanonymousになってもローカル付与しない。
- 共有ポリシーもA→logout→Aを検出し、同じユーザーIDという理由で古い応答を採用しない。
- Edgeの取得待ち・JWT取得・401更新・応答待ちにもガードを接続し、別所有者のJWTで再送しない。
- 同一スコープの重複確認だけを同じPromiseへまとめる。旧Aの請求が未完了でも、
  Bの確認がそのPromiseへ巻き込まれない。
- 旧finallyや旧再確認フラグを新しいセッションへ持ち越さない。
  同一ユーザーの再通知では有効な再試行を維持する。
- 同日再試行のキーは同じ。JST日付またぎで再確認された場合は新しい日のキーを使う。
  実際の受領日・streak・XP・宝箱は引き続きサーバー応答を正とする。
- 匿名確定時のローカル付与と、認証済みのエラーをローカル報酬へ変換しない方針を維持する。
  ローカル付与/復元中に認証が変わった場合も、旧スナップショットや受領情報を新状態へ戻さない。

## 自動回帰

- `src/stores/loginBonusSession.test.ts`：実際のWeb/Mobileボーナスストアを使用。
  重複確認、前段フック待ち、旧応答・旧finally、未完了AからBの新確認、
  A→logout→A、SDK先行切替、anonymous不一致、同日再試行、JST日付またぎ、
  同期的な付与中の認証変更を確認する。通信とゲーム報酬アクションは観測可能なモック。
- `packages/core/src/loginBonusSession.test.ts`：認証再確認・応答待ち中の同一ユーザー再ログイン、
  Edgeのstale-session分類、認証済みスコープのローカル付与禁止。
- `packages/core/src/gameCloudSession.test.ts`：実Edge invokerを使い、請求の送信先待ち、
  旧応答、JWT主体不一致、401更新時の別所有者を確認する。
- 既存のローカルstreak/報酬/rollback、クラウド既受領/失敗、hydration回帰を維持する。

## 境界・残る確認

モック回帰の合格をstaging二アカウント・署名済み実機の合格とは扱わない。
既に開始したHTTPや保存I/Oを取り消す保証はない。サーバー確定済み報酬は既存のpull/Realtimeで回収する。
ライフサイクル中に呼んだ確認が専用フックの世代更新で失効した場合は、初期化後のpull・復帰・明示再試行で確認し直す。
この待機を認証ライフサイクルフック内からawaitしない（既存のpull後トリガーはfire-and-forget）。
起動時の全hydration競合、全画面の既表示演出、複数Webタブの協調・原子的な報酬/保存処理は対象外。

stagingで同一アカウントのWeb/Mobile同時受取、応答喪失後の同日再試行、
通信中の切替と元アカウントへの復帰、JST日付またぎを確認する。
同日の二重XP/宝箱がなく、次の日には正しいstreakで受領できることを確認する。
