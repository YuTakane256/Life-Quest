# Web編集フォームのサブタスク差分同期（#826）

## 変更

Webの既存タスク編集では、子の一覧を端末内に保存しても親の更新しかoutboxへ送っていなかった。
追加・名称変更した子のupsertと、削除した子のdeleteを既存RPCへ送る。
完了済みの子の状態は維持し、一括編集の途中で親を一時的に完了させない。

親のキュー保存、子の差分保存、親の完了/未完了通知の順で処理する。
同じタスクの連続編集は順序を保ち、非同期保存の間のログアウト・アカウント切替・親削除後には子を送らない。
未完了の子をすべて削除して完了済みの子だけが残った場合は、既存の報酬台帳を通じて親完了を処理する。
サインイン中の次回繰り返し生成と宝箱はサーバーに任せる。

フォームを開いた後にタスクが変更された場合は、既存の編集競合ガードが保存を拒否して入力を残す。
同期で追加された子を古い一覧で削除しない。サブタスク名の直接編集UIは今回追加していない。
DB/RLS/API、報酬量、既存ID、過去の失敗キュー、通常の接続設定は変更しない。

## 検証

- 単体回帰：追加/名称変更/削除、変更なし、未完了の子の入れ替え・全削除、親完了/再開、
  Undoタイマー取消、遅延保存中のログアウト/A→B/親削除/キュー拒否、連続保存、匿名の報酬と繰り返し。
- WebのPC幅/スマホ幅・ライト/ダーク：編集途中に受信した子を削除しないこと、
  入力の保持、既存の完了競合ガードと繰り返し編集をPlaywrightで確認。
- 専用stagingの承認済みアカウントAで、前回作った検証タスクの通常Webフォームから
  `Check sync step`を削除し、`Web edited child 20261025`を追加して更新。
  DBで旧子のsoft delete・新子の保存・親未完了・期限/重要度/タグの維持を確認した。
