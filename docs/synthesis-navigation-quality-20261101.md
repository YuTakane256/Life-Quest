# Webの画面移動を越えた合成再試行（2026-11-01）

計画④ / #699・#901 / T07。PR #900マージ後のmain `b43d6dc6`からの修正。

## 不具合と変更

[Webの在庫UI](../src/components/character/InventorySection.tsx)が合成フックを画面内で生成していたため、失敗後にタスク等へ移動すると素材・冪等キー・再送案内を失い、戻っても同じ操作を再試行できなかった。送信中の画面移動では処理中の排他状態も失い、別の在庫画面から再度要求できる経路があった。

既にMobileが使う構成と同様に、[合成操作provider](../src/components/character/InventoryOperationsProvider.tsx)を[App](../src/App.tsx)のルート切替・Suspenseの外へ配置する。キャラの在庫プレビューと独立在庫は[同じ操作context](../src/hooks/useInventorySynthesis.ts)を参照する。画面を移動しても同じ素材・同じ冪等キーを保持し、戻ってから既存の「再送」で再試行する。送信中は次の画面でも「合成中…」と排他状態を保持する。

素材選択・フィルタ・確認・結果演出等の画面内状態は既存の画面寿命に従う。旧画面の遅延演出を新画面へ出さない一方、本人の確定した合成結果は既存フックから一度適用する。新しい自動再送・全画面の通知UIは追加しない。

認証切替の判定には既存useGameOperationScopeを使う。AからBへ切り替わるとAの素材/キー/再送案内を破棄し、遅れて届いたAの応答・finallyがBの表示・処理中状態へ触れない。アプリ全体のproviderを外した後も旧結果を適用しない。

## 検証

[実Appのルーター回帰](../src/hooks/inventoryNavigation.test.tsx)を追加した。実App/Routesと在庫UI・合成フックを使い、認証・通信・適用先はスタブ、他ページ/共通演出は最小fixtureへ置き換える。実ブラウザーや実回線の合格とはしない。

最初の3件は修正前2失敗/1成功。合成失敗後の在庫→タスク→キャラで再送案内/同素材/同キーを保持、送信中の移動と二重操作の拒否、離脱中A/B切替と新キー/送信owner B、遅延A応答によるB操作の汚染防止、App全体のunmount後の結果破棄の5件を確認する。同期品質コマンドにも含める。

既存の在庫選択テストでは、分離した画面用hookのmock先を新context hookへ変更した。選択・売却・認証切替等の既存assertionは維持し、providerの配線は新しい実App回帰で確認する。全体・型・Lint・ビルド・独立レビュー・CIはPRとIssueに記録する。レイアウト・素材を変えないため比較画像追加なし。

## 実stagingの前提と残り

承認済み専用staging Aへ通常認証し、本人RLSでinventory_items / charactersだけを読み取った。装備は未装備の木の指輪1個、XP390・消化数10で、必要な同レアリティ3個を満たさなかった。ゲームデータを変更せず、資格情報・ユーザーID・tokenを公開しない。素材やXPを直接投入したり、既存の装備を消費していない。

したがってT07の実合成・成功応答喪失・両端同期・再起動は未確認のまま残す。素材を通常利用で揃えた後に確認する。今回のUI/通信スタブ回帰を実stagingの合格へ読み替えない。

保持は同じ起動中のApp/認証セッション内に限る。ブラウザー再読込・OS終了後の永続的な再試行や、全ゲーム操作の再起動復帰は対象外。DB/RLS/API/保存形式/報酬ルール/依存・Nativeの実装は維持する。公開/配布/デプロイ・自動マージをせず、④継続、⑤へ進まない。
