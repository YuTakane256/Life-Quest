# Mobile手動統合：候補復元・認証境界・再試行・設定画面

対象: #733。[初回移行の分離](migration-session-isolation.md)で対象外にした手動統合を、
候補取得から表示・承認・送信・結果表示まで1つの変更で扱います。
[ADR-011](adr/011-web-first-migration.md)どおり、ユーザーが承認するまで自動統合しません。

## まとめて修正したこと

1. **候補が消える問題**: クラウドpullで一覧が置換されても、ユーザー別の初回バックアップから
   未統合のタスク・習慣・習慣記録を候補へ復元します。現在の端末データもID単位で重ね、
   同じIDは現在の編集を優先します。クラウドのID/client_idと一致するものは削除済み行も含め除外。
   壊れたバックアップは消さず、確認エラーを表示します。ゲーム進行やXPは統合しません。
   合成後の候補が1回の上限（タスク2,000・習慣500・記録50,000）を超える場合は
   送信せず明示エラーにします。サーバーのサニタイザによる無通知の部分成功を防ぎます。
2. **候補の帰属**: 認証通知のスコープと実セッションが一致するときだけ候補を発行します。
   候補の所有者・スナップショット・スコープをメモリ内のWeakMapへ保持し、コピーや任意の
   オブジェクト、ログアウト/別アカウント/A→B→Aをまたぐ古い候補は送信しません。
3. **送信・再試行**: 同じ候補の同時承認は1つのPromiseを共有し、成功後も再送しません。
   通信失敗・応答喪失・Web移行待ちの再試行では、候補取得時の本文と冪等キーを維持します。
   保存済みバックアップは変更/削除せず、失敗時の候補も保持します。
4. **トークンの所有者**: 共有Invokerの任意オプション`expectedUserId`で、token取得・401 refresh後に
   SDKのセッション所有者を照合します。認証通知より先にSDKのセッションが変わった場合も
   別ユーザーのtokenで旧候補を送信しません。所有者が不明なら送信しません。
   本人確認は引き続きサーバーのJWT検証です。オプションなしの呼び出しは従来どおりです。
5. **設定画面**: スコープ変更を非同期フックの前に通知し、古いメール・候補・統合メッセージ・
   退会確認欄・パスワード入力を破棄します。重なった候補取得・旧送信結果・画面離脱後の結果を
   反映しません。二重タップを同期的に抑止し、確認失敗には再確認ボタンを用意。
   成功メッセージは候補が消えても表示します。ログアウト説明も表示ストアのクリアと整合させます。
   初回認証が進行中に画面を開いた場合も、非同期認証フックの完了後に候補を読みます。
   既存の同一ユーザー候補を作り直すのではなく、初期化を追い越した空候補の確定を防ぎます。

新しい共有スコープ通知は「ユーザーIDが変わった時」だけ発火します。同一ユーザーの
再通知では既存候補を失効させません。購読側の例外でも認証フックを止めず、購読内でさらに
認証状態が変わっても古い通知・フックを再開しません。従来のフックの順序は維持します。

## 自動テスト

```bash
npx vitest run apps/mobile/src/platform/manualContentImport.test.ts apps/mobile/src/hooks/useMobileAccountImport.test.ts apps/mobile/src/screens/SettingsScreen.test.ts packages/core/src/authLifecycle.test.ts packages/core/src/edgeFunctions.test.ts
```

- 候補復元は実ストア・ユーザー別のモック保存領域で確認。バックアップを削除せず、
  クラウド墓標やclient_idを除外し、習慣記録も重複しないことを検証します。
- 承認・HTTP送信は実共有Invokerと制御可能なPromiseで確認。切替、token所有者の不一致、
  重複承認、本文/冪等キーの保持、Web移行待ち、古い成功応答を検証します。
- Reactフックをマウントして、取得の追越し・切替・遅いfinally・離脱・失敗/再確認を検証。
  SettingsScreen本体もnative部品をDOMスタブにして、成功文言の残留、再確認ボタン、退会確認の破棄を操作します。
  これはiOS/Androidのネイティブ描画・レイアウト・キーボードの合格証拠ではありません。

## 境界と残る確認

- DB・Edge FunctionのHTTP本文・報酬量・既存バックアップの保存形式は変更しません。
  `expectedUserId`はHTTP本文へ送らず、サーバーの所有者はJWTだけで決まります。
- 同じ候補の再送キーはメモリ上の承認単位です。再起動や候補の再取得をまたぐ同じレスポンスの
  再現は保証しません。サーバーの既存`unique(user_id, client_id)`による重複防止も維持します。
- 上限超過データの自動分割移行は未実装です。部分送信や削除は行わず、明示エラーで保持します。
- 開始済みHTTPの取消/巻き戻しや、退会と保存I/Oの原子性は保証しません。
  オフライン/不正キャッシュの完全性、複数タブ/端末の協調もこの変更だけでは合格としません。
- 実Supabaseの2アカウント・Web↔Mobile・オフライン再送、署名済み実機、両テーマのネイティブ表示は
  全体の品質確認として残します。今回のUIテストを実機スクリーンショットやストア公開準備の代替とは扱いません。

実行結果・CI 3件・独立レビューはPR本文に記録し、自動マージはしません。
