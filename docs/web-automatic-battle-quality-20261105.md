# Web自動戦闘の非表示・認証・古い時計の停止（2026-11-05）

計画④ / #699・#913 / T07。#912マージ後のmain `3473346e`が基準。

## 問題と変更

[マップ画面](../src/pages/MapBattlePage.tsx)はfightingの間にsetIntervalを作り、毎回その時点のストアへ通常攻撃していた。タブ非表示でも攻撃が進み、停止前に予約された処理が届くと、画面離脱後・別戦闘・別認証セッションにも作用する。clearIntervalだけでは既に予約された古い呼出しの論理的な無効化にならない。

[Web自動戦闘フック](../src/hooks/useAutomaticBattle.ts)へ時計を移し、表示中のマップ・同じ戦闘・同じ認証世代の条件を満たす場合だけ進める。非表示中/非表示での初期表示は停止し、表示へ戻ると新しい一間隔を待って再開する。非表示中の経過時間をまとめて攻撃せず、重複したvisible通知で時計をずらさない。イベント到着前にdocumentが非表示になった場合も、tick自身が確認して停止する。

時計を止めるたびに世代を更新し、以前の呼出しを拒否する。戦闘開始ごとに固定されたplayerSnapshotとステージ・attempt・modeを照合し、同じfighting状態でも別試行へ攻撃しない。認証切替は同期的に停止し、古いAの戦闘を表示切替で復活させない。初回ログイン時に匿名runtimeが残る場合は、この時計のsnapshot等に一致する実行中local戦闘だけをidleへ戻す。保存進行・所持品は残し、既に置き換わった戦闘は清掃しない。アンマウントでは時計・visibility listener・認証購読を解除する。

通常の1000ms間隔、同一所有者の認証通知、手動スキル中の通常攻撃時計は維持する。勝利/敗北後は停止し、既存エンジン・報酬・結果同期を使用する。Mobileの[既存のfocus/AppState対応](../apps/mobile/src/hooks/useAutomaticBattle.ts)は変更しない。

## 検証

[実マップ・実ゲームストアの回帰](../src/hooks/webAutomaticBattle.test.tsx)を17件追加。MapBattlePage・通常攻撃/スキル/ゲーム・履歴ストアは実装を使用し、開始/結果同期のcontextはスタブ。jsdomのvisibility getter/eventとfake timerでタイミングを制御し、停止前に予約済みだったcallbackも明示的に実行する。

基本14件は修正前8失敗/6成功。非表示・初期非表示・古い時計・画面離脱・別戦闘・別アカウント・A再ログイン・イベント遅延時の問題を再現した。追加1件は匿名の勝利/XP/最高到達/履歴が従来どおり一回分に留まることを確認する。追加の独立レビューで、別タブから初回ログインすると匿名戦闘が停止したまま残るP2を確認した。2件の回帰を追加して修正前1失敗/16成功を再現し、上記の一致するlocal runtimeだけを戻す処理で解消する。修正後に確認する範囲:

- StrictModeでも一間隔につき1攻撃。非表示で停止し、復帰後は一間隔待って再開する。
- 初期非表示、重複visible通知、非表示イベント未到着時のtickを処理する。
- 非表示/再表示前の旧時計、マップ離脱後の旧処理、新しい試行へ切替後の旧処理は攻撃しない。
- A/B切替・A→logout→Aでも旧時計を復活させず、新しいB戦闘だけが新しい時計で進む。
- 同一所有者通知と手動スキルでは通常攻撃の間隔を変更しない。
- 勝利/idleで攻撃を止め、cloud未確定報酬を勝手に付与しない。匿名勝利の報酬/進行/履歴を重ねない。
- 実認証ストアフックを登録し、マップを残した匿名→初回ログインでは一致する旧local戦闘だけをidleへ戻す。保存XP/ガチャ回数を維持し、新しい戦闘を開始できる。先に置き換わった別のlocal戦闘は清掃しない。

[Mobileの既存回帰](../src/hooks/mobileAutomaticBattle.test.tsx)、開始/結果の画面移動・再読込・マップ表示の既存回帰も併せて確認する。同期品質コマンドにも新規ファイルを追加。全体・型・Lint・ビルド・独立レビュー・最終HEADの通常CI3件の結果はPR/Issueへ記録する。

## 範囲と残り

Webのdocument.visibilityState/visibilitychangeとマップ画面の寿命が対象。windowのblurだけで非表示扱いにはしない。実ブラウザー全種類の背景タブ制御、OSサスペンド/復帰、実stagingの認証切替や戦闘再送の合格とは区別する。タイマーを使う他の機能や、再起動後の同一attempt継続をまとめて保証しない。

エンジンの数値・報酬ルール・DB/RLS/API・保存形式・依存/Nativeは変更しない。実ユーザー/staging・秘密値・利用中データの操作、初期化/削除、配布/デプロイ/マージは行わない。画面構成/素材変更なし、比較画像追加なし。④継続、⑤移行や全体の安全性認定は未宣言。
