# 報酬演出の遅延処理と通知境界（#743）

## 対象と問題

Webの宝箱・レベルアップ・ログインボーナスは、閉じる操作の300ms後に
通知ストアを無条件にクリアしていた。その間に別の通知が到着すると、新しい通知まで消える。
また、宝箱の「バトルへ」は100ms後の画面移動をunmount後も実行できた。

これは報酬の付与処理ではなく、付与済みの結果を表示する演出の問題。
DB・報酬計算・保存形式・画面レイアウトは変更せず、データ初期化をしない。
Mobileのログインボーナスは即時に閉じ、レベルアップは画面内表示のため、同じタイマー修正は不要。

## 修正

- `useRewardEventTimers`が通知オブジェクト・マウント・認証スコープごとにタイマーを管理する。
- 実行直前にストア内のオブジェクトを再照合する。Reactの再描画/cleanupより先に
  新通知が入っても、旧タイマーは新通知を消さない。同じID・同日付の別オブジェクトも区別する。
- 通知交代、unmount、認証スコープ変更で待機中タイマーを解除する。
  スコープ変更はA→logout→Aも失効、同一ユーザーの重複通知は継続として扱う。
- 宝箱の900ms開封演出・1500ms誤閉じガード・100ms画面移動、
  レベルアップの4500ms自動閉じ、各通知の300ms後のクリアに適用する。
- 認証スコープ変更時はストア初期化フックの完了を待たず古いモーダルを隠す。
  通知はストアから削除せず、その後の新しい通知は通常どおり表示・操作できる。
- 通常のボタン・背景・Escape操作と表示時間、ライト/ダークのスタイルは維持する。

## 自動検証

`src/components/ui/rewardOverlayTimers.test.tsx`は実コンポーネント・実Zustandストアを
React DOM/StrictModeでマウントする。画面移動だけをモック化し、時間はfake timersで制御する。

- 3種類の通常閉じと、300ms以内の通知交代
- 同じID/日付でも別イベントなら新しい通知を維持
- React effect cleanup前のストア交代で旧処理を停止
- unmount、A→logout→A、同一ユーザー再通知
- ストアに旧通知が残っていても認証切替で隠れ、新通知は通常操作できる
- レベルアップの自動閉じと、新通知での表示時間リセット
- 宝箱の開封中交代、通常のマップ移動、交代/unmount/別アカウント後の移動停止

## 境界・残る確認

新規レイアウトや表示素材の変更はないため、比較画像の追加はしない。
DOM回帰の合格をiOS/Android実機・staging認証での合格とは扱わない。
全画面の通知・トースト・通信エラーバナーを認証境界で統一した変更ではない。
報酬処理やサーバー請求の中断・原子化、複数タブの演出連携、通知キューの導入は対象外。
既存どおり単一のpending通知を表示し、未表示の全通知を順番に再生する保証は追加しない。
