# 受信設定の本人確認と反映途中の認証切替（2026-11-07）

計画④ / #699・#947。#946マージ後のmain `e17c7ac0`を基準とする。

## 問題と修正

共有`extractSyncedSettings`はuser_settingsの最初の行を選んでいたため、本人以外の行が先にある場合もその設定を使い、PKと所有者の不一致・削除済み・不正な版や初期版・未知項目だけの設定も明確に拒否していなかった。Web/Mobileの反映処理は設定適用時の認証世代を確認せず、ゲーム受信の購読がA→Bへ切り替えた後もAの設定を適用する。Webではテーマ・モーション・通知が別ストアのため、テーマの書込が認証切替を起こした後にも残りの書込が続く。

[共有抽出処理](../packages/core/src/cloudCache.ts)へ本人IDを必須化し、該当PKの行だけを選ぶ。user_id一致・非削除・安全な整数の更新版（>1）を確認する。settingsは非配列のオブジェクトで、同期対象4項目のうち少なくとも1項目が明示されている必要がある。空/未知項目だけの値を設定初期化の指示としない。各値の正規化は従来どおりプラットフォーム側へ委ね、部分設定に欠けた値を既定値へ丸める互換性も維持する。

[Web](../src/platform/cloudSync.ts)と[Mobile](../apps/mobile/src/platform/cloudSeed.ts)は反映処理の入口で捕捉した認証スコープの本人IDで設定を選び、適用前に同じ世代かを確認する。Webは別ストアへの各書込前にも確認し、途中でログアウト/別アカウント/同じAへの再ログインが始まったら残りを適用しない。Mobileは既存どおり4項目を一度のsetStateで反映する。認証スコープの判定はJWT検証・DBのRLSの代替ではない。

## 検証

[Web/Mobileの実ストア・キャッシュ回帰31件](../src/platform/cloudSettingsOwner.test.ts)を追加。初期25件は修正前21失敗/4成功。修正後は追加の既定値/部分設定/途中ログアウト・再ログインも含む関連6ファイル113件が成功。

- 本人の4項目、明示的なsystem/通知OFF、既存の不正値の正規化と部分設定の互換。
- 別所有者・PK/owner不一致・削除済み・初期/不正な版・配列・空/未知項目だけの行は現在設定を維持。
- 別所有者の行が先でも本人の行を選び、匿名状態では本人向け設定を取り込まない。
- ゲーム受信中のA→Bと、Webのテーマ書込中のA→B/logout/Aへの再ログインで、旧設定の残りを適用しない。
- 通知済みID/習慣通知日を保持し、受信から追加の送信を行わない。

既存の共有抽出テストを新契約へ合わせ、Web/Mobileの既存正常受信テストは本人ログインを明示する。実DB統合2ファイルの抽出呼出も既存のテストユーザーIDを渡す。新規DBケースは追加しない。同期品質unitコマンドへ新テストを加える。全体テスト・型検査・Lint・secrets・ビルド・CI3件・独立レビューの最終結果はPR/Issueへ記録する。
