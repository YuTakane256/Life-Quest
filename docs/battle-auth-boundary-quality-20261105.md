# 画面外の認証切替とlocal戦闘の隔離（2026-11-05）

計画④ / #699・#917 / T07。#916マージ後のmain `018cceb9` が基準。

## 問題と変更

#914/#916の自動戦闘フックは、表示中の戦闘を認証切替で片付ける。しかしWebでマップから離れる、Mobileでblur/disabledになると、その購読は解除される。未seedの匿名移行元データには実行中local戦闘も残るため、復帰時の新しい時計が古い戦闘を進める経路があった。

アプリ起動中に登録する[Web認証ストア](../src/platform/authStores.ts)と[Mobile認証ストア](../apps/mobile/src/platform/authStores.ts)でも、実行中local戦闘の不変snapshot/actorsと認証世代を追跡する。通知が変わったとき、旧世代に属する実行中local戦闘だけを待機状態へ戻す。処理は非同期の移行・同期フックより前に実行し、画面や自動攻撃時計の有無に依存しない。

通常のターンや無関係なストア書込みで同じsnapshotの世代を更新しない。先行する認証購読が新しい世代で別snapshotの戦闘を開始した場合は、それを消さない。同一所有者通知、完了済みlocal結果、保存済みXP・進行・装備・未開封宝箱・報酬台帳・移行元タスクは保持する。cloud/seededの既存清掃、表示中の自動攻撃フックの保護は維持する。登録解除ではストア購読と認証購読を両方解除する。

実行中runtimeの扱いだけを変える。DB/RLS/API・認証SDK・保存形式・同期/移行本体・報酬計算・依存は変更しない。サーバー上のbattle attemptを取り消す処理でもない。

## 検証

[画面なしの認証境界回帰](../src/hooks/battleAuthBoundary.test.ts)を18件追加し、実Web/Mobileストアと認証登録を使って以下を検証する。AsyncStorageとMobileログインボーナス境界はスタブ。

- 初回ログイン・別アカウント・ログアウト/再ログインで、非同期処理前に旧local runtimeを片付ける。
- 保存進行/宝箱/台帳を維持し、新しい戦闘を開始できる。
- 同一所有者通知と完了済みlocal結果を保ち、新世代の別戦闘は巻き込まない。
- 先行購読による無関係な書込みで旧戦闘を新世代に付け替えない。
- 登録解除後に購読が作用しない。

[実Webマップ回帰](../src/hooks/webAutomaticBattle.test.tsx)に離脱→ログイン→再表示を1件、[Mobileフック回帰](../src/hooks/mobileAutomaticBattle.test.tsx)にblur/disabled→ログイン→復帰を2件追加する。MobileのuseFocusEffect/AppStateはJSスタブであり、実画面のタブ移動やOS操作ではない。既存の両authStoresの未seed移行元テスト4件も、実startBattleで「進行は保持、実行中runtimeは隔離」の契約へ更新する。

上記5ファイルの最終テストを旧実装へ適用すると17失敗/88成功。修正後は105件すべて成功した。全体・同期品質・型検査・Lint・secrets・Web/PWAビルド・匿名Android出力・独立レビュー・最終HEADの通常CI3件の結果はPR/Issueへ記録する。
