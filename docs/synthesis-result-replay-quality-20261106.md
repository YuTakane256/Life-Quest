# 合成結果の遅延再生：売却・消費済み装備の復活を防ぐ（2026-11-06）

計画④ / #699・#929 / T07。#928マージ後のmain `f8d0d398`が基準。

## 問題と変更

[Webストア](../src/stores/useGameStore.ts)と[Mobileストア](../apps/mobile/src/stores/useMobileGameStore.ts)のapplyCloudSynthesisResultは、同じ結果IDの装備が存在しなければ、常にテンプレートから装備を作っていた。先に同期で結果を受信し、その結果が売却・次の合成で消費された後に元の成功応答や同じ結果が再適用されると、削除済みの装備を復活させる。サーバーの冪等性だけでは、その古い結果をクライアントが再生成することを防げない。

既存の結果装備があれば、そのオブジェクト・装備状態をそのまま返す。結果が無い場合は、対象素材が1個以上まだストアに残るときだけ従来どおり生成し、素材の除去と無関係な装備の保持を行う。素材も結果も無い場合は古い結果を推測で生成せずnullを返す。将来の売却・再合成で確定した状態を遅い応答で巻き戻さない。未知テンプレートの素材除去は維持する。

素材が全部なく、結果も未受信という曖昧な状態では、応答だけで装備を即時表示せず、通常のpullから正しい所持品を受け取る方針とする。新しい強制pullや自動再送は追加しない。成功応答自体は確定済みとして扱い、nullから新しい結果表示やローカル抽選へ変換しない。保存形式・DB/RLS/API・素材数・抽選/報酬・依存は変更しない。

## 検証

[受信・遅延応答回帰14件](../src/platform/synthesisResultSeed.test.ts)は、Web/Mobileそれぞれで7条件を確認する。実cache/canonical seed、ゲームストア、合成判断処理を使い、受信行と遅延した通信はfixtureにする。

- 通常応答は素材を一度だけ消費し、同じ結果の再適用でも重複しない。
- 同期先行で既に装備済みの結果は、装備状態とオブジェクトを保持する。
- 結果の売却を受信後、遅い初回応答/再適用で復活させず、売却後のXPを保持する。
- 結果が次の合成へ消費された受信状態では、次の結果を残し、元の装備を作り直さない。
- 素材も結果も無い曖昧な状態で推測生成しない。
- 素材の一部だけが残る場合は初回適用を維持する。
- 未知テンプレートでも素材は除去し、無関係な装備とXPを保持する。

修正前6失敗/8成功、修正後14件すべて成功。各遅延応答の直後、後続のpullで誤りが修復される前に確認する。関連5ファイル106件も成功し、同期品質unit対象へ追加する。
