# 受信同期のカーソル制御情報検証（2026-10-31）

## 問題

受信結果は型キャストでPullBatchとして扱い、制御情報を検査する前にキャッシュへ適用していた。
文字列/不正な数値のnext_cursor、booleanでないhas_more、has_more=trueのまま進まないカーソル等で、不要な適用や受信の繰り返しが起こる経路を修正する。実ユーザーでの発生履歴を調査した記録ではない。

## 変更

[共有受信処理](../packages/core/src/cloudPull.ts)で、次を適用前に検証する。

- 開始カーソルは0以上のJavaScript安全整数。無効ならRPC前に拒否する。
- 応答rootは配列以外のobjectで、next_cursor/has_moreはown data property。継承値やgetterに頼らず読み取り、検査失敗は固定エラーへ戻す。
- next_cursorは開始位置以上の安全整数、has_moreはboolean。続きがある場合はカーソルが前進することを要求する。
- 検査済みの制御値を適用前に取り出し、非同期の適用後もその値で保存と継続を判断する。

[Web](../src/platform/cloudSync.ts)/[Mobile](../apps/mobile/src/platform/cloudSync.ts)のRPC戻り値はunknownとして共有fetcherへ渡し、未検証の型キャストを外す。共有runner側も独立して検査し、テスト・別アダプターからの不正応答を適用しない。
所有者/トークン固定と401待機は維持。不正制御情報は既存の再試行可能な失敗表示にし、再ログインを要求する認証エラーとはしない。

不正なページの適用・キャッシュ保存・カーソル前進は行わない。先行ページが成功していた場合はその確定分を保持し、次回は最後に保存できたカーソルから受信する。既存データやキューの消去・巻き戻しを追加しない。

## 互換性と範囲

終了ページの同じカーソル、未知の将来メタデータ、既存の正常ページを許容する。DBのbigint自体の制約を変更するものではないが、JavaScriptで正確に表現できない値は丸めて進めず拒否する。
DB/RLS/サーバーAPI/保存キー・形式/報酬/依存版、キャッシュの行変換は変更しない。

**検証対象はページ制御情報のみ。** 各テーブルの存在・配列形状、各行の全フィールド/所有者/参照整合性、受信全体のバイト数/時間、単調に前進し続ける大量ページの上限までは追加検証しない。RLSやサーバー認可、既存キャッシュ変換の代替ではない。

## 検証

[共有境界回帰](../packages/core/src/cloudPullEnvelope.test.ts)の最初14件で修正前13失敗/1成功を確認した。不正root/数値/フラグ/無進捗をデータ適用前に拒否し、同じカーソルで再試行する。開始値、継承/getter、検査例外、適用中の制御値変更、途中ページ失敗からの復帰も確認する。
[両版セッション回帰](../src/platform/cloudSyncSession.test.ts)ではキャッシュ・表示・カーソル・成功時刻の保持と通常再試行を確認する。

[実DB統合](../supabase/integration/two-client-sync.test.ts)にp_max_versions=1で複数ページを受信するケースを追加。通常受信と同じキャッシュへ収束し、最後の空ページではカーソルを書き直さないことを確認する。環境変数のない通常テストではskipし、Supabase CIで実行する。
画面配置・素材の変更はないため、比較画像は追加しない。

計画④と[#871](https://github.com/YuTakane256/Life-Quest/issues/871)の確認は継続。実ユーザー/staging・秘密値・利用中データを操作せず、配布・デプロイ・自動マージは行わない。⑤への移行や全同期データの安全性保証を意味しない。
