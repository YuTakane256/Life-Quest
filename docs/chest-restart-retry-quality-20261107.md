# 宝箱を起動し直した後に再送する

WebとMobileでは、キャラ画面に残っている未開封の宝箱をもう一度選ぶと、同じアカウント・宝箱の組み合わせから同じ開封キーを再現します。起動時に開封を自動送信することはありません。同期ですでに確定した場合は、獲得履歴と持ち物から結果を確認できます。

新たに確定した開封では従来どおり演出が出ます。以前確定したキーの応答を受けた場合は通常の同期を行い、売却や合成済みの装備を持ち物へ戻しません。青色の宝箱で解放された戦闘も、サーバーから受け取った状態に従います。同期で未開封表示が解消しなければ、再送できます。

新しいクライアントが過去のEdge応答を受けた場合も、通常の同期で結果を確認します。同時に同じキーで開封した場合も、DBが先に確定した応答を判別します。配布時はSQLの更新、`open_chest` Edge Function、クライアントの順に適用すると、新規開封の演出を維持できます。旧クライアントが利用する従来キーの応答形式はそのままです。

WebとMobileの画面テストでは、アプリ全体を作り直して既存の保存から再送します。ローカルDBとEdgeのテストでは、送信前、青箱の確定後の応答喪失、木箱の確定後に別経路で装備を売却した場合を検証します。実端末プロセスの終了・再起動と、合成操作の再送は④の別項目です。
