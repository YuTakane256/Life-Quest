# 退会確認・送信・後始末のアカウント帰属

Issue: [#785](https://github.com/YuTakane256/Life-Quest/issues/785)。計画④のアカウント導線の安全性修正。

## 変更

- Web/Mobileの退会確認に対象のメールアドレス（ない場合はAppleアカウント）を明示する。
  確認したuserId・認証世代・画面寿命を固定し、正確な「削除」入力を要求する。
  認証切替・ログアウト/再ログイン・取消/再確認・アンマウント・Nativeタブ離脱後の古い確認を拒否する。
- 同じ有効な退会要求の連打をまとめる。SDKセッションを照会し、表示した本人と一致するときだけ
  既存の共有Invokerへ `expectedUserId` / `isActive` を渡す。JWT照会・401更新後も別人のトークンでは送らない。
- 確認画面と要求それぞれでSDKの認証イベントを直接購読する。Mobileの報酬復元が待機中で、
  共有ライフサイクルの切替が未反映でも旧確認/要求を失効させる。要求前のSDK A→B→Aも旧承認を復活させない。
  購読は画面破棄/要求完了時に解除し、SDK callback内では非同期SDK処理をawaitしない。
- RPC応答・端末片付け・ログアウトの待機後に帰属を再確認する。片付けの各工程の開始前にも確認し、
  切替後に新アカウントの同期停止・メモリ初期化・ログアウトを開始しない。
- 自分の退会によるログアウトは成功として扱い、完了した匿名スコープでのみ成功/片付け失敗の案内を表示する。
  別アカウントや旧要求のfinallyで、新しい要求の待機表示・メッセージを上書きしない。
- 削除応答が不明な場合は未削除と断定せず、自動再送せずにアカウント状態の確認を案内する。
  SDKセッション確認で失敗した場合は、削除要求をまだ送信していない旨を区別する。
  Apple手動失効の案内は正常完了時・端末後始末の失敗時の両方で維持する。

Webのアカウント照会も認証切替時に更新し、遅延した旧照会で別人を表示しない。
認証フォーム全体や、既存の他の認証操作のすべての非同期処理を作り直すものではない。

## 境界・公開前に残す確認

- 本PRは画面全面統一ではなく、安全性修正を分けたPR。認証済み確認画面はUIテストのテストダブルで検証する。
  本番認証情報の投入・実アカウント削除・実削除RPCは実行しない。匿名画像を退会動作の証拠として掲載しない。
- サーバーへ渡った削除要求や、開始済みのSDK/ストレージ処理を強制取消する機能ではない。
  確認したAの要求がすでに受理された場合、認証切替後でもAのサーバー削除が完了する可能性がある。
  その旧結果ではBの後続片付けを開始しない。開始済みのA専用namespace削除も撤回できない。
- RPC処理開始後の画面離脱だけでは、同じアカウントの必要な後始末を放棄しない。
  端末片付けはサーバー成功後のみ。同じスコープの工程失敗は残工程を試みるが、認証切替は次の工程を止める。
  匿名の `quest-board-*` キーや他アカウントのnamespaceを退会の削除対象に追加しない。
- 結果不明/途中切替で未実行となった端末片付けの自動再開、認証SDK全体の排他制御、既存キャッシュ保存方式の再設計は含めない。
- DB/API/保存形式/報酬計算の変更なし。stagingの実アカウント退会・再ログイン、Apple有効の署名済みビルドでの
  失効/再同意、実機/Android検証は#699/#700に残す。匿名parityでは代替しない。

PR後の独立レビューと既存CI3つを確認し、自動マージしない。
