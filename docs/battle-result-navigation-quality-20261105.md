# Webの画面移動を越えた戦闘結果の同期・再送（2026-11-05）

計画④ / #699・#907 / T07。PR #904マージ後のmain `9404dd8b`からの修正。

## 不具合と変更

[マップ画面](../src/pages/MapBattlePage.tsx)で結果同期フックを生成していたため、勝利/敗北の結果送信に失敗した後、タスク等へ移動して戻ると、同じattemptに対して別の冪等キーで自動送信していた。処理中の移動でも新しいフックが要求を送る。サーバー側の既存冪等処理とは別に、画面移動で再送の判断・行動列のスナップショット・排他が失われる問題である。認証通知が表示ストア清掃に先行する場合、新規フックが旧Aの戦闘をBへ結び直すことも再現した。

[結果同期provider](../src/components/battle/BattleResultProvider.tsx)を[App](../src/App.tsx)のRoutes/Suspense外に置き、マップ画面は[同じcontext](../src/hooks/useBattleResult.ts)を使う。新しいattemptの自動送信は、[既存フック](../src/hooks/useCloudBattleResolve.ts)への引数でマップ表示中に限定する。タスク画面で起動しただけでは、保存された未確定戦闘の認証確認・結果送信を新たに始めない。

開始済み要求の状態・失敗情報・キー・行動列のコピーは同じApp内で保持する。戻っただけでは自動再送せず、既存の「再送」で同じattempt/行動列/キーを送る。本人の確定応答は離脱先の画面のまま既存ストアへ一度反映し、次の戦闘や画面移動を自動開始しない。次回マップ表示時に結果を表示する。

既存の認証scope・attempt binding・ストアの適用ガードは維持する。旧Aの結果/再送情報をBへ持ち越さず、遅れたA応答やfinallyがBの処理を解除しない。App全体のunmount後は旧結果を適用しない。同期が先に同じ結果を確定した場合も、XP・履歴を重複させない。

## 検証

[実App・マップ画面の回帰](../src/hooks/battleNavigation.test.tsx)を8件追加。App/BrowserRouter/MapBattlePage/ゲームストア/戦闘履歴ストアは実装を使い、認証・通信と無関係なページ・通知・演出はスタブとする。実ブラウザー・実回線の合格とは区別する。

修正前は4失敗/4成功。失敗/処理中の画面復帰での重複送信、敗北の自動再送、認証清掃前の旧戦闘の再結合を再現した。修正後に確認する範囲:

- 失敗→タスク→マップで自動再送なし。明示的再送は同じattempt・変更前の行動列・同じキーで、連打を抑止。
- 処理中の移動/復帰でも一要求のまま次へ/マップへの操作を保留。離脱中の確定でXP・履歴1回、現在routeを維持し、マップへ戻ると確定結果を表示。
- 敗北の再送でXPを付与せず、結果確定後に再挑戦を許可。
- 離脱中のA/B切替後にBの別戦闘だけを反映。旧A応答でBの同期を解除しない。
- 認証通知がストア清掃より先でも旧AのattemptをBで再送しない。
- App全体のunmount後の応答は無効。
- 同期先行で結果が確定済みならXP・履歴を再適用しない。
- 無関係な起動routeでは結果送信せず、StrictModeでマップへ入ると一回送信する。

同期品質コマンドにも追加する。既存マップ表示テストはmock先だけ新contextへ変更し、assertionを維持する。宝箱/合成のAppテストには未使用の結果同期API stubを追加する。全体・型・Lint・ビルド・独立レビュー・同じHEADのCI3件の最終結果はPR/Issueに記録する。

## 範囲と残り

同じ起動中Appと認証セッションの画面移動が対象。ブラウザー再読込/OS終了後のキー永続化、未確定戦闘の実再起動、戦闘開始要求・自動攻撃の画面寿命、Nativeの画面寿命は今回変更しない。実stagingの応答喪失は[既存の限定実測](staging-battle-reward-retry-20261027.md)を維持し、今回を新しい実staging確認とはしない。

DB/RLS/API/保存形式/報酬ルール・台帳/依存/Nativeを維持する。実ユーザー/staging・秘密値・利用中データへ操作せず、公開・配布・デプロイ・自動マージしない。レイアウト/素材変更なし、比較画像追加なし。④継続、⑤移行や安全性全体の認定は未宣言。
