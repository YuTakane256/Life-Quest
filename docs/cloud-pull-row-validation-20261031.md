# 同期受信行の検証とページ再試行（2026-10-31）

計画④ / #699・#871。PR #896マージ後のmain `b09843df`からの修正。

## 問題と変更

[共有キャッシュ](../packages/core/src/cloudCache.ts)は、既知テーブルが配列でない場合や行・PKが不正な場合に読み飛ばしていた。[受信runner](../packages/core/src/cloudPull.ts)はそれを正常適用として受信位置を保存するため、正常な応答に戻ってもその行を通常の差分で再取得できない。版番号もNumber変換による比較だけで、欠落・文字列・非有限値等を受け入れていた。

既知テーブルが存在する場合は配列、各行は非null・非配列object、版番号は正の安全整数、テーブルごとのPKは非空文字列であることを要求する。PKはid、user_id、date、habit_idとdateの組。version/PK/テーブルはown data propertyから読み、継承値やアクセサを採用しない。エラーは値やcauseを含まない固定文言 `cloud pull rows invalid`とする。

入力キャッシュは変更せず、全体を正常に処理できた新しいキャッシュだけを返す。途中のテーブル・行が不正ならページ全体が失敗し、両版のcache代入・永続保存・表示更新・カーソル保存より前に止まる。先に確定したページは保持し、既存の同期失敗表示から通常再試行すると、直近の成功確認位置から再取得する。行の削除・切り詰め・キュー消去で成功扱いにはしない。

行mapへの保存にはown propertyを定義する。`__proto__`への通常代入がmapのprototypeを変えてその行を消してしまう問題を防ぎ、`constructor`等も通常のキーとして保持する。入力のPKを別のIDへ書き換えない。

## 互換性と範囲

- テーブル省略・空配列・未知の将来項目は既存互換として許容。全12テーブルの必須化はしない。
- 墓標、複合PK、同じ版の再適用、古い版の上書き拒否、表示用snapshot変換は維持する。
- Web/Mobileは同じ既存関数を使うため、プラットフォーム別の分岐は追加しない。
- DB/RLS/サーバーAPI、保存キー・形式、報酬計算/台帳、依存、認証/トークン固定、outbox先行、前回のカーソル保存成功確認は変更しない。
- 全行owner/参照整合性、UUID/日付形式、全表示項目、ページcursorと各row versionの範囲、重複行、受信量/時間上限の包括検証ではない。認可は既存の認証固定とサーバー権限を維持する。
- 保存済み旧キャッシュの全検証・修復や、原子的複数キー保存・任意クラッシュ・実ストレージ全障害への保証ではない。
