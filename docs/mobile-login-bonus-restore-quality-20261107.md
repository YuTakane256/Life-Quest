# Mobileログインボーナス：匿名保存と本人の受取状態を分離する（2026-11-07）

計画④ / #699・#945。#944マージ後のmain `27603559`を基準とする。

## 問題と修正

[Mobileログインボーナス](../apps/mobile/src/stores/useMobileLoginBonusStore.ts)のpersist mergeは匿名保存を`anonymousState`だけでなく、表示/判定用の`lastLoginDate`と`streak`にも無条件に復元していた。読込待ち中に認証フックが本人のクラウドセッションを開始すると、その後に届いた匿名の当日記録が本人の受取済み状態へ混ざる。`checkDailyLogin`は本人の記録が当日以降ならサーバー確認を省略するため、未受取の本人のボーナスを確認できない。また、本人の受信済み日付/連続日数も古い匿名保存で置き換わる。

匿名履歴はこれまでどおり正規化して`anonymousState`へ復元する。`activeCloudUserId`がない場合にだけ表示用の日付/連続日数へも反映し、クラウド表示中は本人の現在値を保持する。ログアウト時には既存処理で匿名履歴へ戻るため、匿名保存を捨てずに本人との混在を防ぐ。報酬の付与や受取済み判定のルール、サーバーの正本は変更しない。

## 検証

[実persistの回帰12件](../apps/mobile/src/stores/mobileLoginBonusRestore.test.ts)を追加。AsyncStorageと認証SDK/クラウド応答をスタブにし、実認証ライフサイクル・セッション開始/終了・受取判定を通す。修正前8失敗/4成功、修正後は関連4ファイル47件成功。

- 旧version 1の移行とversion 2の匿名保存を読込中にログインする。読込完了前は待機、完了後は匿名の当日記録があっても本人のサーバー確認を1回行う。
- サーバーが新規受取/受取済みのどちらでも本人の日付/連続日数を採用し、新規受取だけ演出を表示する。ローカルXP/宝箱付与は呼ばない。
- 通常の匿名復元と当日の再受取抑止、本人の受信済み記録/演出/再試行状態の保持、A→B、読込中のログアウト、匿名履歴の正規化を検証する。
- 保存内の操作名/所有者/演出は取り込まない。クラウド表示中も匿名履歴だけをversion 2で保存し、重複読込は最新の匿名履歴を維持する。

同期品質unitコマンドにも追加する。全体テスト・型検査・Lint・secrets・ビルド・通常CI3件・独立レビューの確定結果はPR/Issueに記録する。実DB/Edgeの新規ケースは追加しない。
