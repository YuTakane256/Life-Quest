# 装備の売却・合成：確認操作と結果通知の境界（#757）

## 確認した問題

Webの売却確認とNativeの売却/合成Alertは、確認時の装備IDだけを使って後から実行できた。
確認を開いている間にログアウト・別アカウントへの切替や同期が起きると、同じIDの別の内容を
売却/合成し得る。Nativeではタブが非表示でもコンポーネントが残り、古いAlertのcallbackも残る。

既存のクラウド合成フックは**呼出し開始後**の帰属を保護しているが、Alert表示から呼出し開始までの
確認待ちはその外側だった。加えて、画面側の合成結果表示・表示終了タイマーは、古い画面や通知に帰属していなかった。
再送ボタンは返された合成結果を表示していなかった。

## 修正

- coreの確認ガードが承認した装備をコピーし、確定直前に現在の装備と全フィールドを比較する。
  削除・装着・同IDの内容変更では何も消費/送信しない。同値のpull cloneや無関係な装備追加は許可する。
- 確認callbackは一度だけ使用できる。Nativeのキャンセルや別の確認で古いcallbackは実行できない。
- Web/Nativeの薄いReactスコープが認証世代・画面寿命・表示タイマーを管理する。
  Nativeはタブblurでも失効し、戻っても古い確認は復活しない。
- 同一ユーザーの重複認証通知は維持する。A→logout→Aは別世代として失効する。
- 再描画前の古い選択/開始イベントも、描画元の認証スコープを検証して拒否する。
- 認証切替で選択・Webの確認画面・結果通知を破棄する。NativeのOS Alert自体を強制的に閉じる
  APIは使わないが、古いAlertを確定しても副作用は起こさない。
- 合成と再送の成功結果は同じ表示経路を使う。古いPromiseの完了を切替後/離脱後の画面へ表示しない。
- Webの売却1500ms/合成3000ms通知は、別の通知を古いタイマーで消さない。離脱/認証切替でタイマーを解除する。
- Nativeの合成対象は、確認画面で承認した表示中の3件を固定する。フィルター外の古い選択IDを混ぜない。

DB・API・保存形式・報酬/抽選計算・サーバーの冪等性を変更しない。
確認後に始まるHTTPと素材検証は既存の合成フック/サーバーが引き続き担当する。
売却も既存のストアとoutbox経路を維持する。

## 自動確認

- `packages/core/src/inventoryConfirmation.test.ts`：承認内容のコピー、全フィールドの変更、削除、
  装着、同値clone、無関係な追加、無効スコープ、空/重複選択、二度確定。
- `src/components/character/inventoryInteractionSession.test.tsx`：実Web/Native画面とストアを
  React StrictModeで実行。Native部品/Alert/focusと通信フックはDOMアダプター/モックで制御する。
  実際の確認callbackを保存して、切替/アンマウント後にも呼び出し、副作用がないことを検証する。
  同値pull・同一ユーザー通知、再描画前の切替、再送結果、前の通知タイマー、Nativeのcancel/blur/再フォーカスも確認。
- `e2e/inventory.spec.ts`：PC/スマホ幅、ライト/ダークのブラウザーで売却キャンセル→売却確定→
  3個合成→再読込を操作し、7→6→4個の保存結果を確認する。既存の独立画面への移動テストも維持する。
- 既存の売却outbox・クラウド合成/認証帰属テストを含めた全体回帰を実行する。

画面の配置・スタイル・文言は変更しないため、新しい見た目比較画像は追加しない。
ブラウザーE2Eは一時プロファイル、Native回帰はモックAsyncStorageのみを使い、
利用者のシミュレーター/通常保存データは消さない。通常確認用Metro8081は停止しない。

## 残る確認

NativeのOS Alert/フォーカスを実iOS・Android端末で確認した証拠ではない。
実stagingのアカウント切替、通信中の応答喪失/再送、サーバーでの重複消費防止は別途確認する。
開始済みHTTPの取消、素材を待機中ずっと予約する仕組み、合成キーの再起動越し保持は追加しない。
インベントリの独立画面化や全UI統一、他の画面の確認ダイアログ全般はこのPRの完了範囲ではない。
