# 未確定戦闘の保存復元と実DB/Edgeの境界（2026-11-07）

計画④ / #699・#949 / T07。#948マージ後のmain `5595032c`を基準とする。

## 目的

再起動時に未確定の戦闘をどう扱うかを、実ゲームストアの保存形式・persist復元と実DB/Edge/pullを組み合わせて検証する。現在の仕様は、Webは復元不能な戦闘をidleへ戻し、MobileはactiveBattleを復元しない。同じ戦闘の続行や未送信結果の永続再試行機能は未実装であり、今回の検証をその追加と扱わない。

[既存の戦闘統合ファイル](../supabase/integration/battle-seed-race.test.ts)へWeb/Mobile×3条件の6件を追加する。

| 保存時の条件 | 復元・実pull後の期待 |
| --- | --- |
| 戦闘中、結果未送信 | 待機状態へ戻り、attemptはin_progress、報酬0件。結果/行動列の復元・送信や報酬の表示は作らない |
| 勝利したが結果未送信 | クライアント上の勝利を確定報酬にせず、attemptはin_progress、XP/台帳は増えない |
| サーバーで勝利確定後、成功応答を喪失 | 古い保存を復元しても受信で確定XPへ収束。報酬台帳は1件、結果再送や履歴/演出の再作成はしない |

## 方法と検証範囲

開始・戦闘は実Edgeが返す固定スナップショットと実Web/Mobileストアを使う。入力行動列を実エンジンで再生して勝利を確認する。保存は実partialize/serializerを通し、WebはjsdomのlocalStorage、NativeはAsyncStorage APIのメモリ実装に保持する。保存された値を手で組み立てず、ゲームストアのメモリを初期状態へ置き直してから実persist.rehydrateを呼ぶ。

これは**ストアメモリの再作成と保存APIの検証**であり、React App/OSプロセスの終了、実ディスク、認証SDKの起動復帰の試験ではない。Nativeの新しい保存実装は当該テストだけに置き、製品コードは変更しない。

- 復元直後のXPを維持し、Webはidle/attemptなし/行動列なし、MobileはactiveBattleなし・hydration完了になる。
- 実pullを反復しても、サーバー未確定分は付与せず、確定済み分だけを反映する。サーバーの選択ステージ/最高到達も一致する。
- 復元/pull自体からresolve要求を増やさない。Webの戦闘履歴/レベルアップ、Mobileのレベルアップを再生成しない。
- 確定後応答喪失では、**テスト側だけが保存前のキー/行動列を保持**して同じ要求を実Edgeへ再送する。already_resolved/granted=false、character/attemptの版・確定時刻・XP・進行不変、台帳1件を照合する。アプリがキーを永続復元したと主張しない。

既存18件と新規6件の計24件は、既存のloopback限定Supabase CIで実行する。接続先を検証してから一時アカウント/行を作り、そのアカウントだけを後片付けする。新規のworkflow/DB変更/リセットは追加しない。ローカルでDB環境を指定しない場合はskipとし、CIの実行件数と結果をPR/Issueへ記録する。
