# 匿名の達成 → 成長 → 攻略：品質確認

対象: #699。2026-10-14、主要画面統一後の操作・保存回帰。
見た目の画像追加ではなく、実際に報酬を得て攻略へ進めるかを確認します。

## Webで修正したこと

匿名の通常攻撃/スキルで勝利しても、従来は「次へ」の操作まで
`maxClearedStage`が更新されませんでした。「マップへ」戻ると次の敵が
未解放のままになるため、ローカル勝利の時点で進行を記録します。
敗北・戦闘中・未確定のクラウド結果では進行を付与せず、以前の最高到達も
下げません。クラウドの結果確定・XP量・戦闘エンジン・保存形式は変更しません。

単体テストで通常攻撃/スキル勝利、敗北、クラウド未確定、過去ステージ再挑戦、
同じ勝利の再処理、マップ帰還と保存再読み込みを検証します。

```bash
VITE_SUPABASE_URL= VITE_SUPABASE_ANON_KEY= npx playwright test e2e/anonymous-progression.spec.ts
```

新規ブラウザコンテキストで実際にタスク5個を作成・達成し、スターター宝箱を
開けてステージ1を攻略します。報酬や進行を事前投入しません。
PC/スマホ幅で、マップ帰還と再読み込み後のXP、開封状態、次のステージを確認。
通常のブラウザープロファイルは使用しません。

## iOSの既存体験を確認する

インストール済みの `com.yutakane.lifequest.parity` と起動済みのシミュレーターが必要です。
8081の既存Metroを停止してから、以下を実行します。

```bash
npm run mobile:start:anonymous
# 別ターミナル
npm run mobile:parity:progression
# 従来のタスク/習慣の保存回帰
npm run mobile:parity:smoke
```

progressionは専用parityアプリの破棄可能なデータを1回だけクリアし、実際の
タスク達成→スターター開封→戦闘→マップ帰還を操作します。
再起動は `clearState:false` で行い、AsyncStorageの保存を確認します。
同じタスクの再完了でもXP・消化数・宝箱が増えないことを再起動前後に確認。
通常版・preview・サインイン済みデータを対象にしません。

runnerはMetro manifestを事前検査し、匿名parity・クラウド未設定・比較fixtureなし
以外では、Maestroによるデータクリアを開始しません。スクショ用メモリ内の
fixtureを読み直して「保存成功」とする誤判定を防ぎます。

## 残る問題・対象外

- Web匿名の同一タスク再完了はXPが重複付与される。#720で保存台帳と移行を別対応。
  今回のWeb E2Eはこの動作を合格条件へ緩めず、再完了の確認自体を別課題へ分離しています。
- Mobileの完了直後は取消トーストが追加ボタンに重なる。今回の自動フローでは
  本来の5秒の取消猶予終了を待ってから次のタスクを追加します。配置改善は#721で別対応。
- 比較fixtureでの画面操作と、実保存の回帰は別の証拠です。
- クラウド双方向同期・オフライン再送・アカウント切替、Android実機、大小画面/
  大きい文字、Apple認証・通知・退会は今回の合格範囲に含めません。
- ステージ再挑戦は新しいバトルの報酬を許可する既存仕様です。
  「同じ結果の再処理で重複しない」と「再挑戦で報酬を得ない」は異なります。

実行結果はPR本文に記録します。シミュレーターが使えなければ未実行と明記し、
テスト定義だけを実機での成功証拠にしません。
