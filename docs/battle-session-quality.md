# バトル開始・決着・再試行の境界（#739）

## 対象

Web/Mobileのバトル開始から、サーバーでの勝敗確定・再試行まで。
ADR-010の「報酬はattempt単位」「新しい挑戦では再攻略でも報酬を得られる」を維持する。
DB・保存形式・報酬計算・戦闘計算の変更や保存データの初期化は行わない。

## 変更

- 共有の開始ポリシーでも認証スコープを捕捉する。A→logout→Aを同一セッションと取り違えず、
  認証確認・応答待ち中の失効を検出する。SDK主体と画面の捕捉した所有者の不一致でも開始しない。
- 開始・決着のEdge呼び出しへ所有者と有効性確認を渡す。
  送信先の取得待ち・セッション取得・401更新・応答待ちをまたいで別ユーザーのJWTを使用しない。
- 開始フックは同期ゲート、認証切替/アンマウント時の失効、同一キー再試行を管理する。
  MobileもMapScreen内の実装からフックへ抽出し、実フックとして回帰確認する。
- 開始元の戦闘が変わったら、旧開始応答・事前遷移コールバック・旧再試行を適用しない。
  Webの「次へ」成功時の事前遷移は維持する。
- 決着の再試行は同じattempt・操作ID・コピーした行動列を利用する。
  再描画前の連打を止め、旧操作のfinallyが新操作のゲートを解除しない。
- 適用直前にも現在の戦闘を確認し、別戦闘・閉じた戦闘へ結果やエラーを反映しない。
  認証切替/アンマウント後の結果・granted・retry対象も引き継がない。
- 成功適用によってストアがattemptIdをクリアしてもdone/granted表示を維持し、
  再送しない。新しい戦闘/マップへ移れば表示をリセットする。
- React StrictModeのeffect再セットアップで、失効済み要求のために決着が停止しない。
- 起動時にWebの保存済み戦闘が認証復元より先に読まれても、最初の認証確定で再開する。
  既に所有者へ結び付いた旧セッションの戦闘を、切替後に自動で再開することとは区別する。
- 独立レビューで、旧attemptを保持したまま再送だけ止めると「同期中」から戻れない問題を確認。
  既知アカウントからのログアウト/直接切替時は、未seedでもcloud戦闘の一時状態だけを隔離する。
  Webは進行を残してマップへ戻し、Mobileは非永続のactiveBattleを破棄する。
  Mobileのシード済み全ストアクリアにもactiveBattleのクリアを含める。
  初回認証復元・同一ユーザー通知・未seedの匿名由来ローカル戦闘は保持する。
- 匿名のローカル開始と、認証済み/判定不能時にローカル報酬へ切り替えない方針を維持する。

  開始/再試行の連打、認証確認待ちのログアウト、旧AとBの操作競合、別戦闘への移動、
  同一ユーザー通知、認証SDK先行切替、匿名/判定不能、アンマウント、決着成功のattemptクリア、
  行動列コピー、A→logout→A、StrictModeを確認する。
- `packages/core/src/battleStartSession.test.ts`：認証再確認中・応答待ちの同一ユーザー再ログイン、
  SDK主体不一致、認証済みスコープでのanonymousへの切替を確認する。
- `packages/core/src/gameCloudSession.test.ts`：宝箱/合成に加え開始・決着も、送信先待ち、
  旧応答、実Edge invokerでのJWT主体不一致/401更新を検証する。決着行動列のコピーも確認する。
- Web/Mobileアダプタのテストで、所有者・ガードをEdge invokerへ渡す配線を確認する。
- Web/Mobileの`authStores.test.ts`で、実ストアを使いseed有無×ログアウト/直接切替を確認。
  pending attemptが消えてマップに戻れること、Web再hydrationで復活しないこと、
  初回/同一ユーザー通知と匿名移行元データを維持することを検証する。

## 残る実環境確認・境界

実ストアや通信をモックした回帰は、staging二アカウントや署名済み実機試験の代替ではない。
開始済みHTTPの取消は保証しない。サーバーで確定した結果はRealtime/定期pullと冪等性で収束する。
再送キーはフックの生存中に保持し、画面終了/再起動を越える永続化は追加しない。
認証変更で破棄した未確定の戦闘を端末内で勝利/報酬確定へ変換しない。
サーバー未確定の挑戦を切替後に継続する機能は追加せず、マップから新しい挑戦を開始する。
既存のバトル履歴・全演出の認証切替、ログインボーナスの独自フロー全体を完了とは扱わない。

stagingで開始・決着の応答喪失→再試行、通信中の切替→元アカウントへ戻る流れを確認し、
同じattemptで報酬が増えず、新しいattemptの再攻略では報酬が得られることを確認する。
