# ログアウト・アカウント切替と遅延した同期応答

対象: [#725](https://github.com/YuTakane256/Life-Quest/issues/725)、品質確認 #699 / #507。

Web / Mobileで、停止済みの同期handleが取得したデータを、現在の表示用storeへ
適用できる問題を修正します。RPCが完了してから同期状態を公開する時点だけでなく、
結果を適用する前にも、開始時のセッションがまだ有効か確認します。

| 時点 | 起きること | 修正後 |
| --- | --- | --- |
| 1 | Aでpullを開始し、応答を待つ | Aの世代を保持 |
| 2 | ログアウト、またはBへ切替 | Aのhandleを失効 |
| 3 | Aの応答・保存処理が遅れて完了 | Aのstore適用・新規ページ取得・後続保存・cursor更新を行わない |

## 変更

- `CloudPullDeps.isActive`を省略可能なガードとして追加。既存の利用者は従来通り動作。
- cursor読込、RPC、batch適用、cursor保存の待機境界で失効を確認し、
  `has_more`や多重要求による次の周回も止めます。
- Web/Mobileの`isCurrent`は停止フラグと世代の両方を検査。
  cache保存後のseed、同期状態、ログインボーナス再確認、手動再試行・復帰処理にも使用します。
- cache保存では失効後に次のセクションを書き始めません。

## 回帰テスト

```bash
npx vitest run src/platform/cloudSyncSession.test.ts packages/core/src/cloudPull.test.ts packages/core/src/cloudCache.test.ts
```

RPC、ストレージI/O、OSイベントをテスト内で差し替え、実際の認証ライフサイクル登録・
同期handle・共有pull/cache経路を実行します。Webのseed関数とMobileのstore適用境界は
表示先の記録に差し替え、適用されたタスクIDを確認します。既存のstore適用テストは維持します。

- 修正前：Web/Mobileそれぞれ、ログアウト後の応答、A→B後の応答、保存中の切替、
  停止し忘れた旧世代の4ケースが失敗。旧データの再表示・混在を確認。
- 修正後：上記に加え、手動同期のoutbox待機後の切替と、通常起動・失敗・再試行を検査。
- coreはcursor読込・RPC・適用・cursor保存の各待機中の失効、多重要求、
  inactive開始、正常時の再試行、保存セクション間の停止を検査。

## 境界

DB・RPC・保存キー/形式・報酬量・UIは変更しません。新しい画像比較の対象はありません。
通常の同一アカウントでは、適用したbatchの`next_cursor`だけへ進める方針を維持します。

すでに開始したHTTPやストレージI/O自体の取消は行いません。保存途中で切り替えた場合、
開始済みの1回の書き込みは旧ユーザー専用namespaceへ完了し得ますが、その後の保存・
store適用を新たに開始しません。退会時の消去との完全な原子性や、すべての認証関連の
非同期経路を解決したとはしません。

このテストは実Supabaseや署名済み実機の双方向同期の合格証拠ではありません。
stagingでのオフライン復帰・実アカウント切替・Android確認は#699/#700に残します。
