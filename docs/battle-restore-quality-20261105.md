# Web再読み込み後の戦闘復元（2026-11-05）

計画④ / #699・#911 / T07。#905/#906/#910マージ後のmain `6165f20f`からの修正。

## 問題と変更

[Webゲームストア](../src/stores/useGameStore.ts)の復元処理はstatus・敵・残HP等を読み戻す一方、固定playerSnapshot・行動列・クラウドattemptを復元しない。結果として、戦闘中の再読み込みでは`fighting`のままターン処理の必須条件を満たせず停止する。クラウドの勝利/敗北もローカル扱いに変わり、未確定の勝利報酬を獲得済みのように表示する。

復元できないruntimeを再開した扱いにしない。`fighting`、クラウドのrewardMode、未消去attempt、未対応rewardModeを含む保存は、マップの待機状態`idle`へ戻す。敵・行動列・ログ・スキル待機・防御状態・古いHPを残さず、明示操作による新しい開始で固定スナップショットとHPを初期化する。保存済みの最高到達・解放状態・XP・装備・宝箱・報酬台帳は維持し、新たな結果送信・報酬付与・履歴記録・進行加算を行わない。

クラウドの確定済み結果も戦闘画面を再演出せずマップへ戻すが、既に保存された進行/XPはそのまま残す。旧版のローカル勝利/敗北とrewardModeのない旧保存は、既存の「次へ」/「リトライ」を維持する。敵/ログの検証は引き続き既知データと上限に基づく。

同じプロセスの別タブ更新は再読み込みと区別する。[既存のライブ同期](../src/stores/useGameStore.ts)による進行中戦闘の保持を確認し、待機状態への変更を実行中battleへ持ち込まない。Mobileは既に再水和時にactiveBattleを戻さない方式であり、今回は変更しない。

## 検証

[実persist.rehydrate・App・マップの回帰](../src/hooks/battleRestore.test.tsx)を10件追加。BrowserRouter・ゲームストア・保存アダプター・戦闘履歴・マップは実装を使用し、認証/通信・無関係なページ/演出/通知はスタブ。実OSプロセス終了・実staging・実ネットワークの合格とは区別する。

修正前は6失敗/4成功。戦闘中local/cloud、未確定cloud勝利/敗北、確定済みcloud表示、矛盾したattemptメタデータの誤復元を再現。修正後に確認する範囲:

- local戦闘中の復元後は操作可能なマップとなり、新規開始で固定snapshot/HPを作る。
- cloud戦闘中/勝利/敗北はローカル結果として表示せず、古いattemptを送信しない。
- 確定済みcloudの到達/XPを維持し、報酬表示や履歴を重ねない。
- 装備・未開封宝箱・ガチャ回数・報酬台帳を保持する。
- local勝利とモード指定のない旧勝利から「次へ」、local敗北から「リトライ」を使い、XP/履歴を増やさない。
- 匿名の別タブ保存更新でも、実行中のbattle/snapshot/actions/enemyを維持し、新しいXPを取り込む。
- localと称する保存に未消去attemptがある場合も、local勝利として扱わない。

保存テストの準備は匿名の報酬権威を明示し、非同期保存の完了を待ってから保存データを書き込む。無効な台帳キーを使わない。テストの都合で本体の保存ガードを外していない。

[既存の敵/ログ正規化テスト](../src/stores/useGameStore.test.ts)は、新しい復元方針で認めるlocal勝利の入力へ変え、型/上限/既知データへの丸めのassertionを維持する。[クラウド戦闘の既存テスト](../src/stores/useGameStore.cloudBattle.test.ts)にもidle/敵なしの確認を追加する。同期品質コマンドへ新規ファイルを追加し、全体・型・Lint・ビルド・独立レビュー・最終HEADのCI3件の結果をPR/Issueへ記録する。

## 範囲と残り

今回は再読込で復元不可能な戦闘を停止したまま残さず、誤った報酬表示を防ぐ変更。同じ戦闘を再起動後に続行する機能や、所有者付きattempt/行動列/キーの永続復旧は追加しない。未確定クラウド戦闘の実プロセス再起動・同キー再送はT07の残条件であり、[既存の限定実測](staging-battle-reward-retry-20261027.md)を拡張した扱いにはしない。
